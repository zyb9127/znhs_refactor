# 营销话术推荐服务 对外接口文档（直传模式）

| 文档版本 | 日期 | 说明 |
|---|---|---|
| v1.0 | 2026-07-19 | 首版。基于 znhs_refactor 工程实际行为编写，面向各省下游系统（CRM/外呼/客服工作台等）对外提供 |

---

## 1. 概述

### 1.1 功能说明

营销话术推荐服务根据调用方传入的用户信息、产品信息与话术生成上下文，结合各省运营端配置的话术模板，由大模型实时生成**口语化、贴合用户情况的营销话术**，返回给下游系统供坐席/外呼使用。

服务按「省份 + 业务意图」组织技能包，已支持省份：

| province 取值 | 省份 | 已部署业务意图（intent） |
|---|---|---|
| `guangdong`（兼容数字码 `"200"`） | 广东 | `营销活动`、`套餐推荐` |
| `shandong` | 山东 | `营销推荐`、`套餐推荐` |
| `beijing` | 北京 | `套餐推荐`、`套餐升档`、`营销推荐` |
| `fujian` | 福建 | `套餐推荐` |
| `liaoning` | 辽宁 | `套餐推荐` |

> - intent 取值以各省技能包实际发布为准；未发布的 `province + intent` 组合返回 404。
> - 新增省份、新增意图仅需在服务端发布对应技能包，**本接口结构与字段不变**。

### 1.2 接入模式

服务支持两种接入模式，由各省技能包配置决定，**对调用方而言入参结构完全一致**：

| 模式 | 说明 | 调用方配合 |
|---|---|---|
| **直传模式（本文档）** | 调用方已持有用户/产品信息，通过 `extra_info` 直接传入，服务**不再调用任何外部接口**，直接生成话术 | 传 `extra_info`，`extra_data` 传空 |
| 接口查询模式 | 服务按技能包配置回调省份侧数据接口取数（如北京），再生成话术 | 传 `extra_data` 作为接口补充入参 |

本文档仅描述**直传模式**。

### 1.3 处理流程（直传模式）

```
请求 ─→ ① 数据装配：extra_info 写入标准数据域 / 透传通道
     ─→ ② 推荐筛选：recommended_packages 按 topN 筛选（直传产品列表时）
     ─→ ③ 话术生成：按 batch_contexts 逐条匹配话术模板，
            大模型结合上下文数据填充模板占位符，逐产品并发生成话术
     ─→ 响应 recommend_results
```

关键特性：

- **每个推荐产品独立生成一条话术**，多产品并发处理，单条失败自动降级且不影响其他产品；
- 话术模板中的占位符（方括号 `[变量]`、星号 `**（字段名）`、花括号 `{关联变量}` 三种形态）由大模型依据传入的上下文字段**按字段名语义对应填充**，缺失/为 0 的字段自动跳过、不臆造；
- 模板匹配支持「产品 + 环节 + 场景」多维度 12 档优先级链，未命中时逐级兜底（见附录 B）。

## 2. 接口定义

| 项 | 内容 |
|---|---|
| 接口地址 | `POST {host}/znhs/marketing/recommend` |
| 请求格式 | `Content-Type: application/json; charset=utf-8` |
| 响应格式 | `application/json; charset=utf-8` |
| 鉴权 | 无（内网服务，网络层隔离） |
| 建议超时 | 15 秒（多产品并发生成，典型耗时 2~8 秒） |
| 并发建议 | 单实例支持多请求并发；`topN` 与 `batch_contexts` 越大耗时越长，请按 5.3 节控制批量规模 |

## 3. 请求参数

### 3.1 顶层参数总表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `phone` | string | 是 | — | 用户手机号。用于标识用户、日志追踪及接口查询模式取数；直传模式下不参与取数 |
| `intent` | string | 是 | — | 业务意图，需与技能包发布名一致，见 1.1 省份意图表，如 `营销活动`、`套餐升档` |
| `province` | string | 是 | — | 省份代码（小写英文），如 `guangdong`；兼容数字编码，`"200"` 自动映射为 `guangdong` |
| `topN` | int | 否 | 3 | 推荐产品数量上限，取值 `≥1`（无上限）。直传 `recommended_packages` 列表时生效：超出 topN 的产品不生成话术。N 越大耗时越长 |
| `callId` | string | 否 | 服务端生成 | 请求追踪 ID，建议每次请求唯一；响应原样返回，用于全链路日志对账 |
| `extra_data` | object | 否 | `{}` | 接口查询模式的补充入参。**直传模式传空对象 `{}`** |
| `extra_info` | object | 否 | `{}` | **直传模式主体入参**：调用方已持有的用户/产品信息，结构见 3.3 |
| `batch_contexts` | array | 否 | `[]` | 话术生成上下文列表（产品/环节/场景维度），支持单条或多条，结构见 3.4 |

> 未识别字段：顶层传入未定义的字段会被忽略，不影响调用（向前兼容）。

### 3.2 extra_data（直传模式说明）

直传模式下传 `{}` 即可。该字段为接口查询模式预留（如北京回调产品推荐接口时传 `currentMainOffer` 等），直传模式不参与任何处理。

### 3.3 extra_info —— 直传数据主体

#### 3.3.1 设计原则：标准域 + 自定义块

`extra_info` 采用「**7 大标准域 + 任意自定义块**」两层结构，兼顾标准化与灵活性：

- **标准域**：`extra_info` 顶层 key 与下表 7 个标准域同名时，内容被结构化装配，用于模板关联变量（如 `{pkg_brief}`、`{diff_str}`）、套餐差异计算、多产品筛选等系统能力；
- **自定义块**：顶层任意其他 key（如广东现网的 `final_recommendations`、`diff`、`portrait_style`）原样进入话术生成上下文，**字段名即锚点**，供模板占位符按名取用——新增字段**即传即用，无需服务端改任何配置**。

```
extra_info
├── current_package        【标准域】当前套餐信息
├── usage                  【标准域】历史用量
├── tags                   【标准域】用户标签
├── user_info              【标准域】用户基础信息
├── recommended_packages   【标准域】推荐产品列表（多产品推荐入口）
├── user_profile           【标准域】用户画像
├── domain_ext             【标准域】扩展信息（合约/活动/家庭业务等）
└── <任意自定义块>          【自定义】如 final_recommendations / diff / portrait_style ...
```

#### 3.3.2 标准域字段说明

以下字段为**建议集**，均可按需增删；域内自定义子字段同样即传即用。

**① current_package —— 用户当前套餐信息（object）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `package_name` / `offerName` | string | 当前套餐名称 |
| `actual_price` / `initFee` | string/number | 当前套餐实付月费（元） |
| `baseFlow` / `offerFlow` | string/number | 套内流量（GB） |
| `voice_minutes` / `offerVoice` | string/number | 套内语音（分钟） |
| `equity` | string | 权益内容 |
| `broadband` | string | 宽带信息 |
| 其他 | — | 任意自定义字段均可传入 |

**② usage —— 历史用量（object）**，建议三层子结构：

| 字段 | 说明 |
|---|---|
| `data_usage` | 流量用量，如 `近6月平均流量(GB)`、`近6月平均流量饱和度`、`is_frequently_exceed`、`3MonthsOutFlowFee`（近3月超套费用）、`lastedMonth`（最近月份）等 |
| `voice_usage` | 语音用量，如 `近6月平均主叫时长`、`近6月平均语音饱和度` 等 |
| `consumption` | 消费情况，如 `近6月平均月消费`、`近3月平均月消费` 等 |

**③ tags —— 用户标签（object）**：键值对形式，如 `{"融合状态": "单移", "是否老旧套餐": "是", "高频高额超套客户": "否"}`。

**④ user_info —— 用户基础信息（object）**：如 `用户等级`、`internetAge`（网龄/年）、`终端类型`、`开通时间`、`星级` 等。

**⑤ recommended_packages —— 推荐产品列表（array&lt;object&gt;），多产品推荐核心入口**

每个产品一个对象，字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `offerId` / `product_id` | string | 建议 | 产品 ID，与 `batch_contexts.product_id`、模板产品关键词关联 |
| `offerName` | string | 建议 | 产品/套餐名称（兼容别名：`package_name`、`productName`、`name`） |
| `initFee` | string/number | 建议 | 月费/实付价（元）（兼容别名：`monthly_fee`、`price`、`fee`） |
| `offerFlow` | string/number | 否 | 套内流量（GB）（兼容别名：`data_quota`、`dataGB`、`flow`） |
| `offerVoice` | string/number | 否 | 套内语音（分钟）（兼容别名：`voice_quota`、`voiceMinutes`、`voice`） |
| `giftFlow` / `giftVoice` | string/number | 否 | 赠送流量（GB）/ 赠送语音（分钟） |
| `rank` | int | 否 | 推荐顺位，越小越优先；缺省按列表顺序 |
| `recommendation_reason` | string | 否 | 推荐理由，传入后话术会引用该原因 |
| 其他 | — | 否 | 任意产品属性字段（如 `origPrice` 原价、`discountPrice` 优惠价、`privEndMonth` 优惠截止月、`bandwidth` 带宽、`equity` 权益、`broadband` 宽带）均可传入并参与占位符填充 |

> - 传入该列表后：服务端按 `rank` 升序取 **topN** 个产品，**逐产品各生成一条话术**；
> - 未传入（或空列表）：不执行产品筛选，按 `batch_contexts` 的 `product_id`/环节/场景匹配模板生成。

**⑥ user_profile —— 用户画像（object）**：如 `流量偏好`、`使用场景`、`语音偏好`、`communication_style`（沟通风格）、`business_conte`（商机总结）等。

**⑦ domain_ext —— 扩展信息（object）**：无法归入上述 6 域的信息统一放这里，如家庭业务、当前参加的合约/活动、订购关系等。

#### 3.3.3 自定义业务块（广东现网兼容格式）

自定义块为任意命名的 object，整体进入话术生成上下文。广东现网三块结构继续有效：

| 块名 | 字段 | 说明 |
|---|---|---|
| `final_recommendations` | `recommend_package_name` 推荐套餐名称、`recommend_original_price` 原始价格、`recommend_actual_price` 实付价格、`recommend_discount_amount` 减免金额、`recommend_base_flow` 套内流量、`recommend_bonus_flow` 赠送流量、`recommend_total_flow` 总流量、`recommend_voice_minutes` 语音、`recommend_preferential_period` 优惠期（月）、`recommend_equity` 权益、`recommend_broadband` 宽带 | 单产品推荐信息（存量单产品模式，见 5.2） |
| `diff` | `diff_actual_price` 实付价差、`base_flow_diff` 套内流量差、`bonus_flow_diff` 赠送流量差、`voice_minutes_diff` 语音差 | 当前套餐与推荐套餐差异 |
| `portrait_style` | `communication_style` 沟通风格、`business_conte` 商机总结话术 | 画像风格引导 |

> 家庭市场等无用户信息的场景，`extra_info` 传空对象 `{}`，话术直接按模板内容生成。

#### 3.3.4 占位符绑定规则（字段如何进入话术）

话术模板中的占位符有三种形态，**均由大模型依据传入字段按名称语义填充**，调用方只需保证「字段名与占位符名一致」：

| 形态 | 示例 | 来源省份 | 填充规则 |
|---|---|---|---|
| `[字段名]` 方括号 | `[lastedMonth]`、`[3MonthsOutFlowFee]`、`[flow+giftFlow-tf]` | 山东模板 | 按字段名从传入数据取值；支持算术组合表达式，调用方只需传基础字段（如 `flow`、`giftFlow`、`tf`），组合值由模型计算 |
| `**（字段名）` 星号 | `**（recommend_actual_price）`、`**GB（recommend_base_flow）` | 广东模板 | `**` 为值的位置，括号内为字段注释；按字段名取值替换 |
| `{关联变量}` 花括号 | `{cur_brief}`、`{pkg_brief}`、`{diff_str}`、`{usage_line}` | 系统关联变量 | 由系统按标准域自动格式化注入，见附录 C |

填充保障规则（服务端生成规则，对调用方透明）：

1. 上下文中**缺失或为 0** 的字段，对应占位符片段自动跳过，不臆造数值；
2. 同名字段锚点就近对应，不串填（如 `recommend_base_flow` 不会填到 `base_flow_diff`）；
3. 未匹配到任何数据的占位符按模板语义改写为通顺口语，保证话术完整可读。

**调用方实践建议**：新增占位符时，模板中的字段名与 `extra_info` 传入字段名保持一致（建议 snake_case 英文命名），即传即用，无需服务端变更。

### 3.4 batch_contexts —— 话术生成上下文

控制「为哪个产品、在哪个环节、哪个场景」生成话术。数组，支持 1~N 条；**不传或传空数组时**，自动按一条全空上下文处理（通用模板兜底）。

每条目字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product_id` | string | 否 | 产品标识（产品ID或产品名关键词）。非空：与推荐列表/模板产品关键词关联（支持模糊匹配，见下）；为空：对推荐结果自动展开，或走通用模板 |
| `stage` | string | 否 | 环节，与模板「应用环节」对应。取值与各省模板配置对齐，如广东：`个人市场`/`家庭市场`；山东：`场景切入`/`营销推荐`/`营销挽留` |
| `scence` | string | 否 | 场景（**接口字段名固定为 scence**），与模板「应用场景」对应，如广东：`开口话术`；山东：`近3个月流量超套`、`表示太贵了` 等 |
| `expand` | bool | 否，默认 false | 枚举模式开关。`true` 且 `scence` 为空时：枚举该 `product_id + stage` 下所有场景，**每个场景各生成一条话术** |

行为规则：

1. **有推荐产品**（传了 `recommended_packages`）：条目内 `product_id` 非空 → 只生成该产品话术；`product_id` 为空 → 对 topN 内**所有推荐产品自动展开**，每产品一条；
2. **无推荐产品**：`product_id` 非空 → 直接以该 ID 匹配话术模板（模板 `product_id` 支持逗号/换行配置多个关键词，与入参**互为子串即命中**，如模板配 `流量` 可命中 `5G流量包`）；`product_id` 为空 → 以 `stage/scence` 匹配通用模板；
3. **多条目批量**：数组中每条独立处理、并发生成，结果按序返回并回显 `stage/scence`；
4. 匹配优先级（从细到粗逐级兜底）：产品+环节+场景 → 产品+环节 → 产品+场景 → 仅产品 →（产品模糊匹配同序4档）→ 通用+环节+场景 → 通用+环节 → 通用+场景 → 意图兜底，详见附录 B。

## 4. 响应参数

### 4.1 响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务码：200 成功；500 服务内部异常；404/422 见 4.3 |
| `message` | string | 结果描述，成功为 `success`，异常时为错误详情 |
| `data` | object | 业务数据，结构见 4.2；异常时为 `null` |
| `other_info` | object/null | 扩展信息。直传模式恒为 `null`；接口查询模式按省份配置透传上游原始报文 |

### 4.2 data 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `callId` | string | 请求追踪 ID，原样回显（未传时为服务端生成值） |
| `phone` | string | 用户手机号，原样回显 |
| `intent` | string | 业务意图，原样回显 |
| `province` | string | 省份代码，原样回显（数字编码如 `200` 按原样返回，不做转换） |
| `recommend_results` | array&lt;object&gt; | 话术结果列表，每项一个「产品 × 环节 × 场景」话术 |

**recommend_results 项字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `product_id` | string | 产品标识。来自推荐产品或 `batch_contexts.product_id`；通用模板兜底时可能为空串 |
| `rank` | int | 推荐顺位（推荐产品自带 rank 或全局序号） |
| `marketing_text` | string | **生成的话术正文**，口语化、无前缀，可直接供坐席使用 |
| `diff_table` | object/null | 差异表格，仅当命中模板配置了差异表变量时返回：`{headers:[...], rows:[{label,current,target,diff},...]}`；否则为 `null` |
| `stage` | string | 环节回显，**仅批量模式**（传了 `batch_contexts`）时返回 |
| `scence` | string | 场景回显，**仅批量模式**时返回；`expand` 枚举模式下为模板实际命中的场景 |

### 4.3 错误码

| HTTP 状态 | 响应体 | 触发条件 | 处理建议 |
|---|---|---|---|
| 200 | `{"code":200,"message":"success","data":{...}}` | 成功（部分话术降级仍返回 200） | 正常解析 |
| 404 | `{"detail":"未找到技能包: province=xx intent=xx"}` | `province + intent` 组合未发布 | 核对 1.1 省份意图表，联系服务端发布技能包 |
| 422 | FastAPI 参数校验默认结构 | 缺必填字段 / `topN` < 1 / 类型错误 | 按校验提示修正入参 |
| 500 | `{"code":500,"message":"<错误详情>","data":null}` | 服务内部异常 | 携带 `callId` 联系服务端排查 |

> 成功响应中个别产品话术生成失败时，该条自动降级为模板兜底话术（可办理引导类通用文案），整体仍返回 200；调用方无需针对降级做特殊处理。

## 5. 多产品推荐接入说明（重点）

广东现网接口的 `final_recommendations` 为**单产品对象**。为支持多产品推荐话术生成，本接口提供两种多产品接入方式，**推荐方式一**。

### 5.1 方式一（推荐）：recommended_packages 标准域列表 + 自动展开

- `extra_info.recommended_packages` 传**产品数组**（字段见 3.3.2-⑤），每个产品一个对象；
- `batch_contexts` 传一条 `product_id` 为空的条目（或直接不传 `batch_contexts`）；
- 服务端按 `rank` 升序取 `topN` 个产品，**逐产品各生成一条话术**，结果按序返回。

适用：推荐结果由调用方推荐引擎产出，需要「TopN 产品各一条话术」的标准多产品场景。

### 5.2 方式二：batch_contexts 多条目指定产品

- `batch_contexts` 传多条，每条指定不同的 `product_id`（可分别指定 `stage/scence`）；
- 每条独立匹配模板、并发生成。

适用：各产品的话术环节/场景不同，或需要对指定产品（而非全量推荐结果）生成话术的场景。

### 5.3 批量规模约束

- 单次请求生成话术总条数 ≈ `topN` × `batch_contexts` 条目数（`expand` 枚举模式下为枚举出的场景数）；
- 受 LLM 并发与单次耗时限制，**建议单次请求总条数 ≤ 10**；条数越多耗时越长，超出请拆分为多次请求。

### 5.4 与广东单产品模式的关系

| 模式 | 数据结构 | 状态 |
|---|---|---|
| 单产品（广东现网） | `final_recommendations` 对象 + `diff` 对象，模板 `**（字段名）` 占位 | **继续兼容**，无需改造 |
| 多产品（本规范新增） | `recommended_packages` 数组（标准域） | 新接入省份/场景推荐使用 |

两种模式可在同一服务内并存，按 `extra_info` 实际传入结构自动生效，互不影响。

## 7. 占位符与字段对照规范

### 7.1 广东模板字段清单（`**（字段名）` 形态）

模板：`product_id` 关键词如 `流量`、`套餐`、`全家享`、`提速`（支持一模板多产品）；`stage`：`个人市场`/`家庭市场`；`scence`：`开口话术`。

| 占位符字段名 | 含义 | 建议传入位置 |
|---|---|---|
| `recommend_package_name` | 推荐套餐名称 | `final_recommendations` |
| `recommend_original_price` | 推荐套餐原始价格（元） | `final_recommendations` |
| `recommend_actual_price` | 推荐套餐实付价格（元/月） | `final_recommendations` |
| `recommend_discount_amount` | 推荐套餐减免金额（元） | `final_recommendations` |
| `recommend_base_flow` | 推荐套餐套内流量（GB） | `final_recommendations` |
| `recommend_bonus_flow` | 推荐套餐赠送流量（GB） | `final_recommendations` |
| `recommend_total_flow` | 推荐套餐总流量（GB，套内+赠送） | `final_recommendations` |
| `recommend_voice_minutes` | 推荐套餐语音（分钟） | `final_recommendations` |
| `recommend_preferential_period` | 推荐套餐优惠期（月） | `final_recommendations` |
| `recommend_equity` / `recommend_broadband` | 权益 / 宽带 | `final_recommendations` |
| `package_name`、`actual_price`、`voice_minutes`、`baseFlow` | 当前套餐名称/实付价/语音/套内流量 | `current_package` |
| `diff_actual_price`、`base_flow_diff`、`bonus_flow_diff`、`voice_minutes_diff` | 价差/流量差/赠送差/语音差 | `diff` |

### 7.2 山东模板字段清单（`[字段名]` 形态）

模板维度：`stage`（环节）∈ `场景切入`/`营销推荐`/`营销挽留`；`scence`（场景）∈ 28 个异议/意向场景（`近3个月流量超套`、`表示太贵了`、`我考虑一下`、`要免费流量`、`想要携转`、`去营业厅咨询`、`明确拒绝不需要办理任何业务` 等，以模板管理端实际配置为准）。

| 变量 | 含义 | 建议传入位置 |
|---|---|---|
| `[lastedMonth]` | 最近账期月份 | `usage.data_usage` |
| `[3MonthsOutFlowFee]` | 近3个月流量超套费用（元） | `usage.data_usage` |
| `[flowStandard]` | 超套后流量资费（元/G） | `usage.data_usage` |
| `[internetAge]` | 网龄（年） | `user_info` |
| `[flow]` | 套餐流量（GB） | 产品对象/`recommended_packages[i]` |
| `[giftFlow]` | 赠送流量（GB） | 产品对象 |
| `[shareFlow]` | 共享流量（GB） | 产品对象 |
| `[totalFlow]` | 总流量（GB） | 产品对象 |
| `[voice]` | 语音分钟数 | 产品对象 |
| `[giftVoice]` | 赠送语音（分钟） | 产品对象 |
| `[voiceTotal]` | 语音合计（分钟） | 产品对象 |
| `[origPrice]` | 套餐原价（元） | 产品对象 |
| `[discountPrice]` | 优惠后价格（元） | 产品对象 |
| `[reducePrice]` | 减免金额（元） | 产品对象 |
| `[discountExpenses]` | 优惠费用（元） | 产品对象 |
| `[bandwidth]` | 宽带带宽（M） | 产品对象 |
| `[privEndMonth]` | 优惠截止月份 | 产品对象 |
| `[telNumStar]` | 用户星级 | `user_info` |
| `[uniProdGrade]` | 统一产品档次 | 产品对象 |
| `[opStaffId]` | 受理工号 | `domain_ext` 或顶层自定义 |
| 算术组合：`[flow+giftFlow]`、`[flow+giftFlow-shareFlow]`、`[flow+giftFlow-tf]`、`[shareFlow-flow]`、`[voice+giftVoice]`、`[voice+giftVoice-voiceTotal]` | 由基础字段运算的组合值 | 只需传基础字段，组合值自动计算 |

> 变量含义按命名与话术语境归纳，最终以各省模板维护方口径为准；新增变量遵循「字段名一致即传即用」规则。

### 7.3 字段命名规范建议

- 统一使用 snake_case 英文命名（兼容现网 camelCase，系统对产品名称/月费/流量/语音 4 组字段内置多别名识别，见 3.3.2-⑤）；
- 数值类字段建议字符串或数字直传、**不带单位**（单位由模板文案控制），如 `"initFee": "59"` 而非 `"59元"`；
- 流量单位统一 GB、语音单位统一分钟、金额单位统一元；服务端具备 MB→GB 等单位归一能力（接口查询模式），直传模式请按约定单位传入；
- 同一字段全链路同名：下游推荐引擎 → `extra_info` → 模板占位符，避免中间改名。

## 8. 健壮性与演进约定

### 8.1 入参健壮性保障

| 场景 | 服务行为 |
|---|---|
| 缺字段/空值 | 对应占位符片段自动跳过，话术保持通顺；`extra_info` 整体为空时按模板原文兜底生成 |
| 多出未识别字段 | 顶层忽略；`extra_info` 内自定义字段原样进入话术上下文，无副作用 |
| `province` 传数字编码 | 自动映射（`200`→`guangdong`），映射表可扩展 |
| `topN` 未传 | 默认 3；< 1 或类型错误返回 422（无上限） |
| `batch_contexts` 未传/空数组 | 自动按一条全空上下文处理（通用模板兜底） |
| 产品字段命名不一致 | 内置 4 组字段别名（名称/月费/流量/语音）自动识别 |
| `product_id` 在推荐列表中找不到 | 以该 ID 构造占位产品，仍按模板匹配生成话术 |
| 模板未命中 | 沿 12 档优先级链逐级兜底至意图级通用模板（附录 B） |
| 个别话术生成失败 | 该条自动降级为通用办理引导话术，其余结果不受影响，整体仍返回 200 |

### 8.2 演进与扩展约定（面向 context 工程持续演进）

1. **新增数据字段**：`extra_info` 任意层级新增字段即传即用，大模型按字段名锚定取用，无需服务端发版；建议归入语义相近的标准域，无法归类的放 `domain_ext`；
2. **新增省份/意图**：服务端发布对应技能包（话术模板、环节场景取值、字段映射均配置化，经 ES/Redis 实时热同步），本接口结构零变更；
3. **新增匹配维度**：`batch_contexts` 条目支持后续扩展新维度键；未识别的键服务端忽略，老调用方无感；
4. **模板演进**：话术模板、占位符、环节/场景取值的新增修改均在运营端配置，实时生效，接口不变；模板占位符三种形态（`[]`、`**`、`{}`）长期并存兼容；
5. **能力扩展**：多产品生成、差异计算（`diff_str`/`diff_table`）、关联变量（附录 C）等服务端能力以配置方式开启，对调用方透明；
6. **兼容承诺**：已发布字段不更名、不删义；废弃字段提前一个版本周期公告（如旧的 `extra_context`/`extra_contexts` 已由 `batch_contexts` 替代，老调用仍可兼容）。

## 附录 C：模板关联变量（`{关联变量}` 形态）与标准域对照

| 关联变量 | 中文标签 | 数据来源 |

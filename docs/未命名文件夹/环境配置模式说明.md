# 环境配置模式说明

本项目通过 **运行环境（environment）** 统一控制：是否走 mock、是否连接 ES/Redis、
LLM 请求头路由、URL 前缀、是否启用灵运鉴权、是否启用 Kafka 等一系列行为。

环境值来源优先级（高 → 低）：

1. 环境变量 `LINGYUN_ENV`（容器 / CI 覆盖，最高优先级）
2. `config/config.json` → `app.environment`
3. 默认 `development`

> 相关实现：`utils/env_config.py`、`services/api_client.py`、`services/llm_service.py`、
> `utils/skill_runtime.py`、`services/kafka_service.py`、`main.py`。

---

## 一、四种环境模式总览

| 维度 | `development` | `gray` | `production` | `production_noauth` ⭐新增 |
| --- | --- | --- | --- | --- |
| 定位 | 本地开发调试 | 灰度环境 | 正式生产 | 生产行为 + 免鉴权（受控测试） |
| 灵运鉴权 | ❌ 默认关闭 | ✅ 强制开启 | ✅ 强制开启 | ❌ **强制关闭** |
| 外部接口 | 🧪 mock 数据 | ✅ 真实接口 | ✅ 真实接口 | ✅ **真实接口** |
| ES / Redis 配置存储 | ❌ 跳过（本地文件） | ✅ 启用 | ✅ 启用 | ✅ **启用** |
| LLM 请求头路由 | 开发头 | 生产头 | 生产头 | **生产头** |
| Kafka（日志/登出） | ❌ 默认关闭 | ✅ 默认开启 | ✅ 默认开启 | ✅ **默认开启** |
| URL 前缀 | `/znhs-gray` | `/znhs-gray` | `/znhs` | `/znhs-gray`（同灰度） |
| 对应前端构建 | dev / dist-gray | dist-gray | dist-prod | dist-gray（同灰度） |
| 热重载 reload | ✅ 开启 | ❌ | ❌ | ❌ |
| 使用场景 | 本地写代码 | 上线前灰度验证 | 正式对外 | 生产环境免登录验证功能 |

> ⭐ `production_noauth` 是本次新增的模式，核心思路：**只关鉴权，其他保持生产行为**。

## 二、各模式详细说明

### 1. development（本地开发）

- **目标**：一台开发机即可跑通，无需连 ES/Redis/真实接口，无需登录。
- **行为**：
  - 外部数据接口返回 mock 数据（`services/api_client.py` 中 `_APP_ENV == "development"` 走全局 mock）。
  - 跳过 ES / Redis，技能配置直接读本地文件（`utils/skill_runtime.py` `IS_DEV=True`）。
  - LLM 使用开发环境请求头（`services/llm_service.py`）。
  - 鉴权默认关闭；如需验证鉴权可显式 `LINGYUN_AUTH_ENABLED=true`。
  - Kafka 默认关闭。
  - 前缀 `/znhs-gray`，`uvicorn` 开启热重载。
- **启动**：
  ```bash
  python main.py
  # 访问 http://127.0.0.1:8000/znhs-gray/SkillManager
  ```

### 2. gray（灰度）

- **目标**：上线前在灰度环境用真实依赖验证。
- **行为**：真实接口、启用 ES/Redis、生产 LLM 头、Kafka 开启、**强制鉴权**，前缀 `/znhs-gray`。
- **启动**：
  ```bash
  # config.json: "environment": "gray"  或
  LINGYUN_ENV=gray python main.py
  # 访问 http://<host>:8000/znhs-gray/...（需灵运登录）
  ```

### 3. production（正式生产）

- **目标**：正式对外服务。
- **行为**：真实接口、启用 ES/Redis、生产 LLM 头、Kafka 开启、**强制鉴权**，前缀 `/znhs`。
- **启动**：
  ```bash
  # config.json: "environment": "production"  或
  LINGYUN_ENV=production python main.py
  # 访问 http://<host>:8000/znhs/...（需灵运登录）
  ```

### 4. production_noauth（生产行为 + 免鉴权）⭐新增

- **目标**：在**受控**的生产/类生产环境中，**免登录**验证页面与功能，同时保证依赖行为与生产一致（真实接口 / 真实 ES/Redis 数据 / 生产 LLM 路由）。
- **与 production 的差异**：① **关闭灵运鉴权**（不安装鉴权中间件，所有路径开放访问）；② URL 前缀使用 `/znhs-gray`（复用灰度前端构建，便于直接访问）。其余依赖行为与 `production` 一致。
- **实现要点**（`utils/env_config.py`）：
  - `production_noauth` 已加入 `_VALID_ENVS`；前缀映射到 `/znhs-gray`。
  - `load_env_specific_config` 中对该环境**强制** `LINGYUN_AUTH_ENABLED=false`。
  - 由于代码中所有「生产行为」判断均为 `== "development"` 走开发分支、否则走生产分支，`production_noauth` 会自动继承全部生产行为（真实接口 / ES/Redis / LLM host 路由 / Kafka），无需改动业务代码。
- **启动**：
  ```bash
  # config.json: "environment": "production_noauth"  或
  LINGYUN_ENV=production_noauth python main.py
  # 访问 http://<host>:8000/znhs-gray/SkillManager（无需登录）
  ```
- **注意**：前缀为 `/znhs-gray`，使用**灰度前端构建**（dist-gray），通过 `/znhs-gray/...` 访问。

> ⚠️ **安全警告**：`production_noauth` 关闭了鉴权，任何人可直接访问所有接口与页面。
> 仅可用于内网 / 受控测试环境的临时验证，**严禁长期用于正式对外生产**。验证完成后请及时切回 `production`。

---

## 三、鉴权控制优先级

`utils/env_config.py` → `load_env_specific_config()` 判定顺序：

1. `LINGYUN_AUTH_DISABLED=true` → 强制关闭（覆盖任何环境，本地联调用）
2. `production_noauth` → 强制关闭
3. `gray` / `production` → 强制开启
4. `development` → 默认关闭，可 `LINGYUN_AUTH_ENABLED=true` 显式开启

## 四、常见问题

**Q：只想临时测试页面、不想改环境，怎么办？**
A：保持 `production`/`gray`，设置环境变量 `LINGYUN_AUTH_DISABLED=true` 即可临时关鉴权，效果与 `production_noauth` 相同，且无需改 `config.json`。若希望作为一种可复用的固定配置，则用 `production_noauth`。

**Q：`production_noauth` 会不会连测试库、发 mock 数据？**
A：不会。它除鉴权外与 `production` 完全一致：走真实接口、真实 ES/Redis、生产 LLM 路由。

**Q：访问路径是 `/znhs-gray` 还是 `/znhs`？**
A：`development`/`gray`/`production_noauth` 为 `/znhs-gray`；`production` 为 `/znhs`。也可用 `ROOT_PATH` 环境变量覆盖。

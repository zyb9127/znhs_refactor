## 1. 项目概述

### 1.1 定位与目标

面向运营商呼叫中心与线上营销场景，为坐席/智能体实时生成"千人千面"的个性化营销话术，解决传统话术生产的四大痛点：

| 痛点 | 本系统对策 |
|------|-----------|
| 话术千篇一律 | 基于用户实时套餐、用量、标签、画像的 Context 工程化 LLM 生成 |
| 数据分散难整合 | 多接口并发取数 + 双层声明式映射收敛到 7 大标准数据域 |
| 省份差异大、系统僵化 | "省份 × 意图"纯配置技能包，扩省扩场景**零代码** |
| 上线周期长 | 运营后台配置即发布、秒级热生效，配置周期从周级压缩到小时级 |

### 1.2 技术栈

| 层次 | 选型 |
|------|------|
| 后端 | Python 3.10 / FastAPI / Pydantic / Loguru / httpx（全异步） |
| 前端运营端 | Vue 3 / Element-Plus / Vite（灰度、生产双 dist 独立挂载） |
| 大模型 | 灵运平台大模型网关（DeepSeek / Qwen3 系列，强制关闭思考模式降时延） |
| 配置存储 | Elasticsearch（3 节点，版本化权威源）+ Redis Cluster（6 节点，热缓存/发布订阅）+ 本地 JSON 原子快照 |
| 鉴权 | 灵运 satoken 中间件（按路径前缀分流灰度/生产客户端） |
| 消息 | Kafka 操作日志（可选，失败不影响主流程） |

### 1.3 已落地规模

- 技能包：**4 省 7 意图**（北京：套餐推荐/套餐升档/营销推荐；山东：套餐推荐/营销推荐；广东：营销活动；海南：流量包活动/套餐升级活动）。
- 话术模板资产：2000+ 条，支持 CSV/Excel 批量导入与智能占位符填充。
- 接入形态：接口查询模式、CTI 直传模式、营销助手统一接口（异步回调）三种。

## 3. 核心技术特点（八大亮点）

### 3.1 纯配置驱动的"省份 × 意图"技能包体系

- 一个技能包 = 两个 JSON 文件（`api_nodes.json` 接口映射 + `biz_config.json` 策略与话术模板），**不包含任何可执行代码**，新增省份/意图/场景完全零代码。
- 运行时 100% 省份无关：`SkillRegistry` 按 `province:intent` 双键加载与缓存执行单元（`core/pipeline.py` 的 StepBundle 缓存），热更新时定向失效，避免同省不同场景配置相互污染。
- 31 省中文名与数字区号码（如 200=广东）统一经 `config/province_mapping.json` 解析，扩省不改代码。

### 3.2 三层配置存储 + 双通道热更新，"诚实失败"发布语义

- **唯一写路径**：全部配置写入收敛到 `services/skill_publisher.py`，前端、AutoConfig、配置智能体均经此入口，杜绝多写分叉。
- **三层存储**：ES 版本化（保留 5 个历史版本，支持一键回滚）→ 本地 JSON（`.tmp` + `os.replace` 原子写）→ Redis 热缓存 + Pub/Sub 广播。
- **双通道同步**：`sync_mode=hybrid` —— Pub/Sub 秒级触达（实测目标 <3s），300s 定时轮询比对 ES 版本号自愈兜底；Pub/Sub 风暴与批量导入均有防广播放大设计（批量 N 条模板压缩为 2 次外部写入）。
- **诚实失败**：ES 写失败则整体发布失败、三层状态零残留，绝不出"半发布"状态；ES 故障时读路径自动降级 Redis/本地文件，服务保持可用。

### 3.3 Context 工程：7 大标准数据域 + 双层声明式映射

- 各省异构接口数据统一收敛为 7 大标准域（`current_package / usage / tags / user_info / recommended_packages / user_profile / domain_ext`），是话术模板消费的唯一事实来源。
- **双层映射管线**（`steps/data_step.py`）：Layer-1 `response_extract` 路径提取为命名中间槽位；Layer-2 `field_transform` 规则处理器注册表（装饰器可插拔），内置 `passthrough / filter_include / filter_exclude / constant` 四类规则与单位换算（MB→GB、分→元，支持 `*.` 通配路径）。
- 健壮性机制：字段名规范化与模糊匹配守护、空域从 `extra_data` 自动回填、推荐列表映射缺失自愈、`source_type=direct` 直传节点复用同一映射管线——**接口查询与直传两种模式共享一套映射引擎**。

### 3.4 12 档话术模板匹配 + 哈希索引加速

- 模板以四元组 `(intent, product_id, stage, scence)` 定位，匹配分三阶段 12 档优先级：产品精确 4 档 → 关键词模糊 4 档（适配广东等描述性产品 ID）→ 通用兜底 4 档，另有宽松兜底（漏传环节/场景时视为不限）与 `expand` 场景枚举模式。
- **TemplateIndex**：模板数 ≥30 时自动构建只读线程安全哈希索引，与线性扫描逐语义等价（有等价性对照测试保障行为不变）。

### 3.5 防幻觉 Prompt 工程

- Prompt 结构化四段：【上下文数据】（逐行 `{占位符}：值` 事实锚点）→【话术模板】→【生成规则】→【缺失事实负向约束】（显式禁止编造、禁止跨域串填、空值删整句）。
- **确定性填槽**：`product/usage/tags` 等事实字段由代码确定注入而非依赖 LLM 转述；生成后残留占位符整句清除；输出统一清洗（去 Markdown、去"话术："前缀、无中文判空并打降级标）。
- 变量标签单一真源 `schemas/standard_domains.json` + 同义别名组锚点对齐，前端"数据流映射"页可视化校验"接口 → 标准域 → 模板变量"闭环。
- 支持用户性格特征（`portrait_style`，效率型/谨慎型等六型）驱动语气与字数分档，实现真正的千人千面。
- 2026-08 Prompt 构建器重构（`engine/prompt_builder.py`），配 114KB oracle 对照测试逐字符比对保证回归无差异。

### 3.6 全链路异步性能工程

| 环节 | 机制 |
|------|------|
| LLM 网关 | 类级共享常驻 httpx 连接池（max 200 / keepalive 100）+ 服务启动 warmup，消除首字冷启动 |
| 下游接口 | 全局共享连接池（max 100），`asyncio.gather` 多接口并发取数；connect 5s / read 30s；重试 2 次线性退避 |
| LLM 并发 | 三级信号量覆盖：技能包 `llm_max_concurrency` > 环境变量 > 全局默认 8；**直传模式按条数自适应全并发**（18 产品即 18 路并行） |
| 缓存 | DataStep 取数结果 TTL 60s 进程内缓存 + **singleflight 单飞防击穿**；StepBundle 按 `province:intent` 缓存 |
| 事件循环保护 | 模板匹配 / Prompt 构建等 CPU 片段放 `asyncio.to_thread`，不阻塞事件循环 |
| LLM 时延 | 强制关闭思考模式（Qwen3 `enable_thinking=False`、DeepSeek `reasoning_effort=low`）；重试 3 次指数退避（上限 10s）；全失败返回空串并打降级标，不阻断主流程 |

### 3.7 三种接入模式 + 营销助手异步链路（2026-08 新落地）

| 模式 | 说明 |
|------|------|
| 接口查询 | 服务并发调用下游接口取数，`extra_data` 经 `{{extra_data.xxx}}` 占位符注入请求模板 |
| CTI 直传 | 坐席侧已推屏的数据经 `extra_info` 直传，DataStep 自动跳过取数，端到端时延最小化；支持顶层直传字段白名单自动折叠 |
| 营销助手统一接口 | `POST /znhs/marketing/preload`：双营销标志过滤 → 按 `activityTypeName` 分组路由同名意图技能包（组间并发）→ 切入/挽留双话术归并 → **先 ack 异步生成，结果回调网关 Redis**（key `preload:{phone}:{callId}:hs`，5 分钟过期）；报文适配收敛于唯一适配层 `utils/marketing_assistant.py`，遵循"零改名"原则 |

### 3.8 配置治理与自动化运营闭环

- **确定性配置 Lint**：`management/config_agent/linter.py` 内置 E101–W108 共 13 类编号检查项，保存时自动巡检；配套 `repairer.py` 自愈修复与 `conflict_detector.py` 同维度模板冲突检测。
- **人在环配置智能体**：只产出修改建议、不直接落盘，人工确认后经唯一写路径发布。
- **接口文档智能解析**：上传 .docx 接口规范，经"解析 → 入参匹配 → 规则映射 → 单位检测 → LLM 补全"流水线自动生成 `api_nodes` 草稿；`management/interface_mapper` 内置 ReAct 式 Function Calling Agent 支持对话式映射修正与全自动建档。
- **AutoConfigAgent**：JSON/Excel 五 Sheet 标准模板 → 生成 → 跑通校验 → 省份级权限校验 → 一键发布并热重载，技能包支持跨包导出/导入、另存为模板、版本备份/回滚。

## 4. 核心链路详述

### 4.1 三步异步管道

```
POST /znhs/marketing/recommend
  │ Step1 DataStep：读取 api_nodes 启用节点 → gather 并发取数
  │   → response_extract（路径→槽位）→ field_transform（规则→7 大标准域）
  │   → 空域回填 / 映射自愈 / 取数缓存（TTL 60s + singleflight）
  │ Step2 RecommendStep：策略插件（DirectStrategy 按 rank 取 TopN，
  │   注册表可扩展）；直传模式不截断调用方产品
  │ Step3 ScriptStep：12 档模板匹配（含 expand 枚举）
  │   → Prompt 构建（事实锚点 + 负向约束）→ 确定性填槽
  │   → 分级信号量控制并发调 LLM（直传全并发）→ 输出清洗
  ▼
{code, data:{recommend_results:[{product_id, rank, marketing_text, diff_table, stage, scence}]}}
```

管道为纯 Python async 实现，**无 LangGraph 等重型框架依赖**，部署轻量；同时保留 `biz_config.pipeline` 组件化分支，可按配置自定义执行流满足复杂场景。

### 4.2 插件机制

- `plugins/recommend_strategy.py`：推荐策略基类 + 注册表，新策略注册即用。
- `plugins/package_diff.py`：套餐差异计算生成 `diff_table`，内置多省份字段别名与套餐名解析月费兜底。
- `plugins/unit_converter.py`：单位换算注册表。

### 4.3 可观测性

- `utils/observability.py`：基于 **contextvars** 的请求级 trace，`callId` 全链路透传，分阶段耗时/降级打标并挂到响应 metadata；`?debug=1` 返回 resource_context、api_calls、llm_prompts 供排障。
- `utils/province_logger.py`：分省四类 JSONL 日志（request/response/llm/api，按天切分、30 天留存、手机号脱敏、2 万字符截断），全程吞异常绝不影响主流程。
- `scripts/province_stats.py`：分省调用量与并发峰值统计（扫描线算法，纯标准库可生产直跑）；`scripts/diag_beijing_keys.py`：ES 键名/映射/占位符三方只读对账诊断。

## 5. 可靠性与工程质量

- **多环境**：`development / gray / production / production_noauth` 四态，环境优先级 `LINGYUN_ENV` > config.json；灰度/生产前端双 dist 同进程挂载；dev 模式自动跳过 ES/Redis 走本地文件。
- **三级 mock 降级**：development 全局 mock → 节点级 `mock_mode` → 网络全败后用接口文档 `mock_response` 兜底并打降级标。
- **测试资产**：19 个测试文件约 7100 行，`tests/run_all.py` 统一入口；关键重构均配 oracle 等价性对照测试（Prompt 构建器逐字符比对、模板索引 vs 线性扫描语义等价）；`tests/测试/` 留存 12 份真实省份现网请求样例。
- **安全边界**：实时接口免鉴权（内网白名单路径），管理端强制 satoken 鉴权且按账号所属省份限制编辑权限；日志手机号脱敏；配置路径段校验防目录穿越。

## 6. 部署与关键参数

| 项目 | 数值/说明 |
|------|-----------|
| 运行环境 | `LINGYUN_ENV=development/gray/production/production_noauth`，`PORT` 默认 8000 |
| LLM 连接池 | max 200 / keepalive 100 / keepalive_expiry 30s，启动 warmup |

| LLM 并发 | 技能包配置 > `ZNHS_LLM_MAX_CONCURRENCY` > 全局默认 8；直传模式自适应全并发 |
| 取数缓存 | TTL 60s（手机号+意图+extra_data 维度），singleflight 防击穿 |
| 配置同步 | Pub/Sub（目标 <3s）+ 轮询 300s 兜底，hybrid 默认 |
| ES 版本 | 每配置保留 5 个历史版本，可一键回滚 |
| 交叉营销回调 | Redis key `preload:{phone}:{callId}:hs`，expire 5 分钟，timeout 5s |

启动：`LINGYUN_ENV=production python3 main.py`；前端构建：`cd frontend && npm run build:artifact`（灰度/生产分别构建）。

## 7. 演进方向

- **Skill 化对外输出**：按《营销智能体skill化技术方案/技术方案.md》，以"能力服务 + 薄 Skill"分层纳入类龙虾智能体生态——本服务作为常驻能力服务暴露能力接口，智能体侧薄 skill 经 HTTP 调用，配置与性能资产全部保留在服务端。
- **可嵌入核心库**：将 `core/ + steps/ + engine/ + plugins/` 收敛为纯 Python 包 `znhs_capability`，未来常驻 worker 型框架可进程内嵌，核心逻辑零分叉。
- **策略智能化**：推荐策略插件从 DirectStrategy 向画像驱动的多策略组合演进；配置智能体从"人在环建议"向"自动修复 + 人工放行"演进。

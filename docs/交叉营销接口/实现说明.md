# 营销助手统一接口 — 实现说明

对应需求：`开发设计思路.txt` 一、需要单独适配营销助手的统一接口入参。

参考文档（同目录）：
- 入参：`灵运前置接口入参示例.txt`、`灵运平台交叉营销接口规范.docx`（一、交叉营销数据来源接口）
- 回调：`交叉营销网关-preload_cache_接口文档.docx`

## 一、一句话结论

「营销助手统一接口」是**直传透传模式下的一种接口规范**，与既有「标准接口」并列。差异只有
两点——**入参形状**和**响应语义**；取数、模板匹配、填槽、话术生成全部复用现有链路。
标记位置在技能包的接口节点上（`api_nodes.<节点>.request_variant`），因此**不改任何已上线
标准接口配置**，默认值 `standard` 即现有行为。

| | 标准接口 | 营销助手统一接口 |
|---|---|---|
| 入参 | `{phone, intent, province, extra_info, batch_contexts}` | `{"params":{"systemId","optType","inputs":{…}}}` |
| 调用地址 | `POST /znhs/marketing/recommend` | `POST /znhs/marketing/preload` |
| 响应 | 同步返回 `recommend_results` | 只回 `{"rtnCode":"0","rtnMsg":"数据接收成功！"}` |
| 结果去向 | HTTP 响应体 | 回调网关写 Redis `preload:{手机号}:{touchNumber}:hs` |

## 二、入参处理规则：零改名

唯一形状适配点：`utils/marketing_assistant.py`，**配置期（调色板/预览/测试报文）与运行期
共用同一函数**，保证「报文里的字段名」＝「配置页勾的字段名」＝「运行时进话术上下文的字段名」。

**后端不改任何业务对象的名称与层级**，只剥掉传输层：

| `params.inputs` 下 | 进 extra_info | 说明 |
|---|---|---|
| `userinfo`（含 `userExtra`） | 原名原层级 | 子字段按原路径勾选：`userinfo.currPrice`、`userinfo.userExtra.last3mFlowSaturation`；运行时按**叶子名**注入，模板写 `{currPrice}` / `{last3mFlowSaturation}` |
| `products[]` | 原名 `products` | 键名不改。多产品链路需要标准域 `recommended_packages`，由 DataStep 按节点配置**只把值**喂进去（`marketing_assistant.resolve_product_list_field`）——对外/调色板/模板始终是 `{products}`，不会出现第二个同义占位符 |
| `userinfo_json[]` | 原样 | 整块引用 `{userinfo_json}`（含多账期趋势），不派生 `usage_current` 之类别名 |
| `ordered_activity_list` / `cancel_activity_3m_list` / `end_activity_6m_list` | 原样 | |
| 报文后续新增的任何业务对象 | 原样 | 全量透传，不需要改代码 |
| `sequenceNo` / `servNumber` / `provinceCode` / `callId` / `staffId` / `staffNo` / `touchNumber` / `systemId` / `optType` | **不进 extra_info** | 网关元数据，只挂在解析对象上供回调使用，避免污染提示词 |

产品列表字段名可在节点上用 `product_list_field` 显式指定（不指定时营销助手规范默认
`products`），留给后续别的接口规范复用；标准接口节点没有这项配置，行为完全不变。

省份：`provinceCode` 为 3 位数字码（规范示例 河南 371、河北 311），映射表在
`config/province_mapping.json → numeric_mapping`，**运维改配置即可扩省/纠错，不必改代码**。
广东现网既有内部码 `200` 保留。

产品 ID：`productId` 追加在 `_DEFAULT_FIELD_ALIASES["product_id"]` **链尾**（`Cmn_flow` 同理追加到
`pkg_flow` 链尾），仅当前面别名都取不到值时才生效，已上线省份取值零变化。

## 三、产品维度的三条业务规则

报文里 `params.inputs.products[]` 的这几个字段不是话术素材，而是**控制字段**：

| 字段 | 作用 | 实现位置 |
|---|---|---|
| `activityTypeName`（活动名称） | 省份 + 活动名称 → **选技能包（场景 skill）** | `routers/cross_sell.py`：按活动名称分组，每组匹配**同名意图**的技能包 |
| `marketingProductFlag` / `marketingActivityFlag` | **是否生成话术** | `utils/marketing_assistant.is_marketable`：任一为否值（`0`/`false`/`no`/`否`）即跳过该产品；字段缺失或为空视为可营销（对端没下发时不能把整批判死） |
| `business_type` / `productId` / `productName` | **匹配话术模板** | `steps/script_step.py` 的候选链，**精确优先**逐个尝试：`productId` → `business_type` → `productName` |

**选技能包**：一次报文里的产品可能属于不同活动，故按 `activityTypeName` 分组，各组并发跑自己的
技能包，结果合并成**一次**回调。运营按活动名称建技能包（意图名 = 活动名称）即可生效，不需要
维护映射表。整批活动名称都没有同名技能包时（存量配置，如意图叫「营销活动」而活动名称是「流量
语音包」），回退到该省份唯一勾选营销助手的技能包 / `default_intent`；但只要本批**有任何**活动名称
精确匹配上，其余没匹配上的活动就不再回退——否则会拿另一个活动的模板生成内容，比不出话术更糟。

**模板匹配顺序**为什么是精确优先：业务类型是一类产品共用的粗粒度维度，若它排在产品 ID 之前，
产品专属模板将永远命不中。三个维度都是**前一个维度没命中任何模板**时才尝试下一个（`business_type`
在标准接口省份的产品对象里不存在，候选自动跳过，已上线省份候选序列逐项不变）。取值字段可用
`biz_config.template_match.product_id_from` / `business_type_from` 覆盖（支持点路径与多候选）。

ID 与标志类字段（`productId` / `activityId` / `activityTypeCode` / 两个 `marketing*Flag`）已加入
`engine/prompt_builder.PKG_FIELD_EXCLUDED_KEYS`，既不出现在调色板，也不会被兜底注入进
提示词——避免把 `2026070113291445801035520` 这类串号念进话术。

## 四、异步响应与回调

规范明确「异步处理仅仅回复是否收到数据」，另有结果获取接口 `BIGMODEL_PRELOADRESULT_POST`，
所以实现为真异步：

```
灵运前置 → POST /znhs/marketing/preload
             ├─ 校验 + 归一 + 路由 → 立即回 {"rtnCode":"0","rtnMsg":"数据接收成功！"}
             └─ 后台任务：pipeline 生成话术 → POST {网关}/api/gateway/preload/cache
                                              {touchNumber, servNumber, identifier:"hs", value, expireMinutes}
下游 → 结果获取接口 → 读 preload:{servNumber}:{touchNumber}:hs
```

回调 `value` 对齐《交叉营销结果获取接口》的 `data`，**一个产品一项**（同一产品的推荐/切入/挽留
话术归并到同一项的不同字段），按入参产品顺序密集排 `rank`：

| 字段 | 来源 |
|---|---|
| `words` | **营销推荐话术**（商品话术，下游取这个）= 配了「推荐」环节则取该环节话术，否则取无环节常规话术，**始终有值** |
| `aiPitchMarketingDesc` | 灵运营销切入话术：**仅当**技能包配了切入环节模板才有值，否则空串 |
| `aiRetentionMarketingDesc` | 灵运挽留指引话术：**仅当**配了挽留环节模板才有值，否则空串 |
| `rank` | 结果内排序 1..N |
| `activityId` / `activityType` | 取自入参产品的 `activityId` / `activityTypeCode`（活动分类编码），本服务不生成 |
| `productId` | 入参产品 ID（与推荐话术回显的 product_id 同源；话术没回显时按位次与入参产品对齐兜底） |
| `aiRecommendReason` / `aiRecommendScore` | 本服务不产出，留空不编造 |

**三条话术相互独立**（对齐上面三个字段）：`words` 是营销推荐话术，`aiPitchMarketingDesc` /
`aiRetentionMarketingDesc` 是**额外**的切入 / 挽留指引话术。一个产品配了「切入、推荐、挽留」三行
环节模板时，三条话术各自生成后归并成一条产品话术，分别填进上面三个字段。最常见的默认形态——技能包
只配普通话术模板时，**只回 `words`，两个 `ai*` 字段为空**。

`routers/cross_sell.build_batch_contexts` 读该技能包的话术模板决定生成哪几条：

- 推荐话术条目 → `words`，**始终生成**：配了「应用环节」= 推荐 的模板则以该环节匹配（`stage=推荐`），
  否则回退到无环节（`stage=""`）常规模板匹配（无环节模板时由 pipeline 自动构造一条，行为与既有一致）；
- 配了「应用环节」= 切入 的模板 → 多生成一条 → `aiPitchMarketingDesc`；
- 配了「应用环节」= 挽留 的模板 → 多生成一条 → `aiRetentionMarketingDesc`。

之所以要判模板存在性：模板匹配在环节维度会逐级降级（产品+环节 → 仅产品 → 通用），没配某环节
模板时传 `stage=该环节` 会命中推荐/通用模板，产出与 `words` 雷同的内容并填进 `ai*` 字段，等于
让下游重复播报。环节名各省叫法不统一，故 `config.json → cross_sell.recommend_stage / pitch_stage /
retention_stage` 配候选列表，取第一个在该技能包模板里真实存在的。

被营销标志挡掉、或所属活动没有技能包可路由的产品，不出现在 `result[]` 里。

`optType` 本期只处理 `0`（营销话术，identifier=`hs`）；只传 `1`/`2` 时正常回收妥但不生成，
日志记录。后续要做 `1-营销推荐`（identifier=`tj`）在同一处扩展即可。

## 五、配置项

`config/config.json → cross_sell`，每项可被环境变量覆盖（部署注入不同网关地址不改文件）：

| 配置 | 环境变量 | 默认 |
|---|---|---|
| `enabled` | `ZNHS_CROSS_SELL_ENABLED` | true |
| `callback_base_url` | `ZNHS_CROSS_SELL_CALLBACK_BASE` | `http://bigmodel.zhiduo.cmos:8080/cslm_crosssell_gateway` |
| `callback_path` | `ZNHS_CROSS_SELL_CALLBACK_PATH` | `/api/gateway/preload/cache` |
| `callback_expire_minutes` | `ZNHS_CROSS_SELL_EXPIRE_MINUTES` | 5 |
| `callback_timeout_seconds` | `ZNHS_CROSS_SELL_TIMEOUT` | 5 |
| `default_intent` | `ZNHS_CROSS_SELL_DEFAULT_INTENT` | 空（不兜底） |
| `recommend_stage` | — | `["推荐","推荐环节","营销推荐"]` |
| `pitch_stage` | — | `["切入","切入环节","营销切入"]` |
| `retention_stage` | — | `["挽留","挽留环节","挽留指引"]` |

意图路由不需要配省份→意图表：先按活动名称找同名意图的技能包（见第三节），整批都没匹配上时才
扫该省份标记了 `request_variant=marketing_assistant` 的技能包（多个时按字典序取首个并告警），
仍没有则用 `default_intent` 兜底，还没有就拒收并告警。**按活动名称建技能包后，同一省份可以有
多个营销助手技能包**，各管一个活动。

## 六、运营配置步骤

1. 技能管理 → 接口配置 → 编辑直传节点：数据来源「透传模式」、映射方式「直接透传字段」、
   接口规范选**「营销助手统一接口」**；
2. 第②步样例框点「填充示例报文」（或粘贴对端真实报文）。注意规范文档里的示例带 `//` 注释、
   不是合法 JSON，需用按钮或自行删注释；
3. 勾选要进话术上下文的透传字段（列出的就是**报文原字段**：`userinfo`、`products`、
   `userinfo_json` 及各自子字段，`userinfo.userExtra` 下的各省个性化字段再展开一级）。产品字段里
   的控制字段带角标（`选技能包` / `控制生成` / `选模板`），提示它们不是话术素材；
4. 保存。营销助手节点的 `mock_response` **保留原始报文不被改写**（它是该节点的样例真源）；
5. 技能包**意图名建议直接用活动名称**（`activityTypeName`，如「流量语音包」），这样该活动的产品会
   精确路由到这个技能包；一个活动一个技能包，模板互不干扰；
6. 话术模板配置（技能管理 → 话术模板）：
   - 「产品 ID」栏填 `productId` / `business_type` / `productName` 任一（弹窗里有从接口样例抽出的
     可选值，点击填入；也支持逗号分隔多关键词做模糊匹配），留空 = 该场景兜底模板；
   - 一个产品可分别建「推荐 / 切入 / 挽留」三行环节模板（环节名见
     `cross_sell.recommend_stage / pitch_stage / retention_stage`），生成后归并为一条产品话术
     （`words` / `aiPitchMarketingDesc` / `aiRetentionMarketingDesc`）；不配「推荐」时 `words`
     取无环节常规话术，不配切入/挽留则对应字段留空；
   - 「模板匹配规则」面板可覆盖各维度的取值字段（模板关联字段 / 业务类型兜底字段 / 环节 / 意图）；
7. 话术模板里按原字段名引用占位符：`{currPrice}`、`{last3mFlowSaturation}`、`{productName}`、
   `{discount_price}` 等；`products` 下的产品字段逐条话术各取自己那条产品的值。

接口列表与模板编辑弹窗都有「营销助手」角标，便于与标准接口区分。

## 六之二、排障：话术只出 words，且提示词里「话术模板」段为空

测试页出现「三条提示词字数完全相同、①上下文数据/②话术模板/③话术要求全空、④其他=完整
Prompt」时，说明**一条 v2 模板都没命中**，走了旧 `prompts` 兜底分支
（`engine/prompt_builder.py` 旧格式路径只填 `other`/`full`，另外三段恒空）。

最常见的根因是**产品列表没喂进标准域 `recommended_packages`**：此时 `ScriptStep` 用空产品
`{}` 走一遍匹配（`steps/script_step.py` 的 `target_pkgs = [{}]`），`product_id` 为空 →
只可能命中「产品 ID 列为空」的通用模板，填了具体产品 ID 的模板一律落空；并且话术结果不回显
`product_id`，回调归并只能按位次兜底。

按顺序自查：

1. 测试页「🧩 产品与模板命中诊断」卡片看**喂入标准域的产品数**。为 0 即命中本节问题；
2. 直传节点三个条件必须同时满足（缺一个产品就进不了标准域，见 `steps/data_step.py`）：
   映射方式 = **直接透传字段**（`direct_mode=passthrough`）、接口规范 = **营销助手统一接口**
   （`request_variant=marketing_assistant`）、透传字段包含 **`products`**；
3. 产品的 `marketingProductFlag` / `marketingActivityFlag` 必须**同时**为真值，否则该产品被
   挡在生成之外（测试页「🚫 被营销标志过滤的产品」卡片会列出）；
4. 生产日志可直接确认：有无
   `[DataStep] 直传节点 X: 产品列表字段 'products' (N 条) 已喂入标准域 recommended_packages`，
   以及 `[ScriptStep] 模板匹配 product_id=` 是否为 `''`。

注意：只把模板「产品 ID」列清空能让模板命中（走通用兜底），但治不了 `product_id` 不回显；
回调侧已对 words/切入/挽留**三个角色各自**做按位次兜底，不会再只剩 words。

**兜底自愈（数据面）**：报文 `products` 带灵运独有字段（营销标志 / `activityTypeName`，判据见
`utils/marketing_assistant.looks_like_marketing_products`）时，即使节点漏勾「营销助手统一接口」，
`DataStep` 也会把该列表喂进标准域并**照样套用营销标志规则**，同时打 WARNING。已上线省份的
产品列表没有这些字段，不受影响。

**但自愈救不了路由**：`activityTypeName` → 技能包的路由（`match_intent_by_activity` /
`resolve_marketing_assistant_intent`）**强制要求**节点标记 `request_variant=marketing_assistant`，
没勾选时线上只能靠全局兜底意图 `cross_sell.default_intent`。配置测试页固定用当前技能包、
不走路由，所以测不出这个问题 —— 故「🧩 产品与模板命中诊断」卡片只要有一项体检不合格就会持续
标红，不因自愈生效而转绿。

## 七、涉及文件

新增：
- `utils/marketing_assistant.py` — 报文识别/归一/请求体转换/回调 value 构造
- `utils/province_code.py` — 省份编码归一（中文名 + 数字码，读配置）
- `services/cross_sell_callback.py` — preload/cache 回调客户端
- `routers/cross_sell.py` — `/marketing/preload` 异步入口 + 按活动名称分组路由 + 环节展开 +
  后台生成 + 合并回调
- `tests/test_marketing_assistant_interface.py` — 59 项用例（含调色板占位符按原名、`products`
  喂标准域后仍逐产品出话术、活动名称路由与回退、营销标志过滤、模板匹配候选顺序、切入/挽留归并；
  `TestStandardModeUnaffected` 专门守「三条新规则不外溢到通用模式」）

改动（均为增量，标准接口行为不变）：
- `routers/realtime.py` — 省码映射外置；营销助手报文打到 `recommend` 时自动识别转发
- `routers/management.py` — 样例剥壳支持新报文；产品样例按节点声明的原名字段找；保存不改写
  原始报文；列表返回 `request_variant`
- `steps/data_step.py` — 直传透传节点按 `resolve_product_list_field` 把原名产品数组的**值**
  喂进标准域 `recommended_packages`（键名不变）；营销助手节点按营销标志过滤产品
- `steps/script_step.py` — `productId` / `Cmn_flow` 追加到别名链尾；模板匹配候选链加入业务类型
  （`pkg_biz_type` 别名 / `template_match.business_type_from`）；「产品列表由调用方直传」判定
  不再写死键名（不限并发对营销助手同样生效）
- `core/context.py` / `steps/recommend_step.py` / `steps/script_step.py` — 「调用方直传的产品数」
  统一到 `FlowContext.caller_supplied_package_count`（按值比对认产品数组，键名不写死；
  RecommendStep 的「不按 topN 截断」与 ScriptStep 的「不限并发」共用同一口径）

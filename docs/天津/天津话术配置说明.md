# 天津营销话术配置说明

本目录下 `天津营销话术导入.csv` 为**可直接导入**的话术模板，列序须与技能包「导入话术模板」弹窗一致：
`场景分类名称, 环节, 意图, 话术匹配ID, 话术内容, 关联变量(可留空), 状态(online/offline)`。
`话术要求` 与 `派生字段` CSV 装不下，需在页面单独配置——下面把两者都备好，直接粘贴即可。

> ⚠️ 该导入弹窗（SkillConfigEditor）是**前端按列位置解析**：第 5 列才是话术内容，且**不按逗号拆分产品**。
> 因此严禁改列序，且每个活动编码单独占一行（3 个安心月包各一行、内容相同），不能合并。

---

## 1. 导入 CSV 说明（共 5 行）

| 列 | 值 / 说明 |
|---|---|
| 场景分类名称 | 备注名（如「安心月包(活动1)」），Mode A 落库时以意图为准，仅作辨识 |
| 环节 | 统一「推荐」，与营销助手 batch_contexts 的推荐环节严格匹配 |
| 意图 | 留空（此列实际写入 scene；营销助手不传 scence，留空才走严格匹配、不落宽松兜底） |
| 话术匹配ID | 填**活动编码**，每个编码单独一行 |
| 话术内容 | 模板正文（含占位符）；必填，否则该行被判空跳过 |
| 关联变量 | 留空即可，系统按接口自动关联、占位符运行时自动匹配 |
| 状态 | online |

**占位符（天津=营销助手透传模式，须用入参/派生的子字段形式，否则填不上）**：

| 动参口径原占位符 | 模板实际占位符 | 取值来源 |
|---|---|---|
| `{超额量}` | `{当月资源[over_flow]}` | 派生 `当月资源`（timeType=0 账期）子字段 |
| `{套餐外上网费}` | `{当月资源[over_flow_fee]}` | 同上 |
| `{超套分钟数}` | `{当月资源[over_voice]}` | 同上 |
| `{套餐外通话费}` | `{当月资源[over_voice_fee]}` | 同上 |
| `{XX}分钟`（国内语音） | `{userinfo[currDomesticVoice]}` | 透传 `userinfo` 子字段 |
| `{XX}流量`（国内流量） | `{userinfo[currDomesticTraffic]}` | 透传 `userinfo` 子字段 |
| `{XX}月份` | 「当月」（文字） | 报文无月份号，当月资源已按 timeType=0 选取 |

子字段语法 `{根[子键]}` 由 `engine/prompt_builder` 支持，`tests/test_derived_fields.py::TestDerivedFieldsInPrompt`
及本次实跑均已验证可填槽；值为空/0 的子字段默认不入正文（配合话术要求做「为 0 或空不展示」）。

导入即写入配置（追加/更新，不清空已有），不会覆盖你单独配的话术要求。

**匹配键提醒**：话术匹配ID 列用的是活动编码。请把该技能包接口配置里
`template_match.product_id_from` 设为 **`activityId`**（因为活动编码对应报文 `activityId`）。
若灵运实际把这些编码放在 `productId` 里，则改回 `productId`，或产品列改填 productId。

活动编码 → 目标业务编码 对照：
- 安心月包（场景1=2031912 / 场景2=2031913）：`20266527188432`、`20266511328323`、`2026645993441`
- 安心套餐28元档：`20266510873112`
- 安心季包（3元）：`20266511751052`

## 2. 派生字段（接口配置 → 派生字段，粘贴 JSON）

已在生产报文220 / mock 两种数据实跑验证通过（0 如实产出、空不产出、饱和度四场景正确）。

模板占位符直接引用 `当月资源`/`userinfo` 的子字段，故**无需**再定义 `超额量` 等标量派生字段；
逻辑判断（推荐场景/账单解释提示/切入场景）在 `when` 里直接用 `当月资源.over_flow_fee` 等路径。

```json
{
  "当月资源":   { "type": "array_find", "from": "userinfo_json", "where": { "timeType": "0" } },
  "上月资源":   { "type": "array_find", "from": "userinfo_json", "where": { "timeType": "1" } },
  "超套费用合计": { "type": "sum", "from": ["当月资源.over_flow_fee", "当月资源.over_voice_fee"] },
  "推荐场景":    { "type": "bucket", "from": "超套费用合计",
                 "rules": [ { "lt": 1, "value": "场景一" }, { "value": "场景二" } ] },
  "账单解释提示": { "type": "bucket", "rules": [
      { "when": { "当月资源.over_flow_fee": { "ne": 0 }, "当月资源.over_flow": { "eq": 0 } }, "value": "请结合账单与资源使用情况为客户解释" },
      { "when": { "当月资源.over_voice_fee": { "ne": 0 }, "当月资源.over_voice": { "eq": 0 } }, "value": "请结合账单与资源使用情况为客户解释" },
      { "value": "" } ] },
  "前三月语音饱和度": { "type": "sum", "from": ["userinfo.userExtra.last3mVoiceSaturation"] },
  "前三月流量饱和度": { "type": "sum", "from": ["userinfo.userExtra.last3mFlowSaturation"] },
  "切入场景":    { "type": "bucket", "rules": [
      { "when": { "前三月语音饱和度": { "gt": 0 }, "前三月流量饱和度": { "eq": 0 } }, "value": "场景1" },
      { "when": { "前三月流量饱和度": { "gt": 0 }, "前三月语音饱和度": { "eq": 0 } }, "value": "场景2" },
      { "when": { "前三月语音饱和度": { "gt": 0 }, "前三月流量饱和度": { "gt": 0 } }, "value": "场景3" } ] }
}
```

> 前 5 个（当月资源/上月资源/超套费用合计/推荐场景/账单解释提示）与当前 `api_nodes.json` 已配置的一致；
> `前三月语音饱和度`/`前三月流量饱和度`/`切入场景` 是安心套餐所需，按需补上即可。

字段计算 vs 逻辑判断（对应页面两组）：
- 字段计算：当月资源、上月资源、超套费用合计、前三月语音饱和度、前三月流量饱和度
- 逻辑判断：推荐场景、账单解释提示、切入场景

## 3. 话术要求（每条模板单独配，粘贴到对应模板的「话术要求」）

**通用（天津共性）**：以模板话术为主体框架，只做占位符填充与轻微顺滑，字数≤150；
凡占位符值为 0 或为空，则不展示对应字段/句子（不要出现「超出0」「**元」等无意义信息）。

### 安心月包（20266527188432 / 20266511328323 / 2026645993441）
```
以模板为主体框架，字数≤150。根据上下文【推荐场景】决定输出哪一段：
- 推荐场景=场景一 → 只输出「场景1」段（安心月包-1元，业务编码2031912）；
- 推荐场景=场景二 → 只输出「场景2」段（安心月包-3元，业务编码2031913）；
- 【推荐场景】为空（无超套费用数据）时不要臆造场景，简要引导可办理安心月包，不虚构业务编码。
占位符{当月资源[over_flow]}{当月资源[over_flow_fee]}{当月资源[over_voice]}{当月资源[over_voice_fee]}按上下文填充；值为0或空则不展示对应字段。
若上下文有【账单解释提示】，解释账单时自然融入该口径。
```

### 安心套餐28元档（20266510873112）
```
以模板为主体框架，字数≤150。先输出「切入语」，{userinfo[currDomesticVoice]}{userinfo[currDomesticTraffic]}按上下文填充，为0或空则不展示该字段。
根据上下文【切入场景】只输出对应一段：场景1/场景2/场景3；【切入场景】为空则不输出场景段，仅保留切入语与月费说明。
结尾保留「月费28元…相当于终身有效」的说明。
```

### 安心季包（20266511751052）
```
以模板为主体框架，字数≤150。占位符{当月资源[over_flow]}{当月资源[over_flow_fee]}按上下文填充，为0或空则不展示对应字段。
若上下文有【账单解释提示】，自然融入解释口径。不虚构业务编码与数值。
```

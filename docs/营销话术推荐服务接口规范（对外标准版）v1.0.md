# 营销话术推荐服务 · 对外接口规范（直传模式）

| 文档版本 | 日期 | 说明 |
|---|---|---|
| v1.0 | 2026-07-19 | 对外标准版。全省统一接口，面向各省下游系统（CRM / 外呼 / 客服工作台）对接 |
| v1.1 | 2026-08-02 | 多产品并发生成落地说明；响应 `product_id` 回显 `offerId`；顶层直传兼容；补充广东多产品入出参样例 |
| v1.1.1 | 2026-08-02 | 响应 `recommend_results[]` 新增独立字段 `offerId`；关联产品优先用 `offerId`，`product_id` 仍回显兼容 |
| v1.1.2 | 2026-08-02 | 默认出参精简为规范字段；`resource_context` / `llm_prompts` 等排障字段仅 `?debug=1` 返回 |

---

## 1. 接口概述

营销话术推荐服务根据调用方传入的用户与产品信息，结合服务端配置的话术模板，由大模型实时生成**口语化、贴合用户情况的营销话术**，供坐席 / 外呼直接使用。

- **全省统一**：所有已接入省份共用同一套接口结构与字段，省份差异由服务端配置承载，**新增省份 / 意图不改变本接口**。
- **直传模式**：调用方已持有用户 / 产品数据，通过 `extra_info` 直接传入，服务不再回调任何外部接口。
- **单 / 多产品统一入参**：产品统一通过 `extra_info.recommended_packages` **数组**传入 —— 单产品传 1 个元素，多产品传多个元素，服务端对 TopN 个产品**逐产品各生成一条话术**，入参结构完全一致。
- **多产品并发生成**：多个产品的话术由服务端异步并发处理，一次性返回全部结果；单产品入参 / 出参形态不变。
- **响应按 offerId 关联产品**：`recommend_results[].offerId` **回显入参产品的 `offerId`**；`product_id` 同步回显同一值（兼容旧对接）。调用方据此把话术关联回对应产品。
- **推荐产品与当前产品比价**：入参提供当前套餐（`current_package`）与推荐产品的可比字段（价格 / 流量 / 语音 / 宽带等），服务端自动逐产品计算差异，产出比价话术（`{diff_str}`）与结构化比价表（响应 `diff_table`），详见第 7 节。

## 2. 接口定义

| 项 | 内容 |
|---|---|
| 接口地址 | `POST {host}/znhs/marketing/recommend` |
| 请求方法 | `POST` |
| 请求格式 | `application/json; charset=utf-8` |

## 3. 请求参数

### 3.1 顶层参数

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `phone` | string | 是 | — | 用户手机号，用于标识用户与日志追踪 |
| `intent` | string | 是 | — | 业务意图，需与服务端发布名一致（见附录 A），如 `营销活动`、`套餐推荐` |
| `province` | string | 是 | — | 省份代码（小写英文），如 `guangdong`；兼容数字码 `"200"`（自动映射为 `guangdong`） |
| `topN` | int | 否 | 3 | 生成话术的产品数量上限，取值 `1~10`；按 `rank` 取前 N 个产品；兼容字符串数字（如 `"1"`） |
| `callId` | string | 否 | 服务端生成 | 请求追踪 ID，建议每次唯一；响应原样回显 |
| `extra_data` | object | 否 | `{}` | 直传模式**固定传空对象 `{}`** |
| `extra_info` | object | 否 | `{}` | **直传数据主体**：用户 / 产品信息，结构见 3.2 |
| `batch_contexts` | array | 否 | `[]` | 话术生成上下文（环节 / 场景），结构见 3.3；不传按通用模板兜底 |

> 顶层传入的未定义字段将被忽略，不影响调用（向前兼容）。  
> **例外（兼容）**：部分标准域若误写在顶层，服务端会自动折叠进 `extra_info`，见附录 B。

### 3.2 extra_info（直传数据主体）

采用「**标准域 + 自定义块**」结构，全部为可选、可空：

| 顶层 key | 类型 | 归类 | 说明 |
|---|---|---|---|
| `current_package` | object | 标准域 | 用户当前套餐，字段见 3.2.1 |
| `recommended_packages` | array | 标准域 | **产品列表（单 / 多产品统一入口）**，字段见 3.2.2 |
| `usage` | object | 标准域 | 历史用量，建议三层：`data_usage` / `voice_usage` / `consumption` |
| `tags` | object | 标准域 | 用户标签键值对，如 `{"融合状态":"单移","是否老旧套餐":"是"}` |
| `user_info` | object | 标准域 | 用户基础信息（等级 / 网龄 `internetAge` / 星级等） |
| `user_profile` | object | 标准域 | 用户画像（流量偏好 / 使用场景 / 语音偏好等） |
| `domain_ext` | object | 标准域 | 无法归入上述域的扩展信息（合约 / 活动 / 家庭业务等） |
| `<任意自定义块>` | object | 自定义 | 任意命名对象（如 `portrait_style`），**字段名即锚点**，整体进入话术上下文，供模板占位符按名取用，即传即用无需服务端改配置 |

> 标准域会被结构化装配（套餐差异计算、多产品筛选、关联变量等）；自定义块原样进入上下文。无用户信息场景（如家庭市场），`extra_info` 可传空对象 `{}`，按模板原文生成。

#### 3.2.1 current_package —— 当前套餐（object）

| 字段 | 类型 | 说明 |
|---|---|---|
| `offerName` / `package_name` | string | 当前套餐名称 |
| `initFee` | string/number | 当前套餐月费（元）。**比价字段**，别名 `fee` / `price` / `monthly_fee` |
| `offerFlow` | string/number | 套内流量（GB）。**比价字段**，别名 `flow` / `data` / `data_quota` |
| `offerVoice` | string/number | 套内语音（分钟）。**比价字段**，别名 `voice` / `minutes` / `voice_quota` |
| `bandWidth` | string/number | 宽带带宽。**比价字段**，别名 `bandwidth` / `broadband_speed` |
| `equity` | string | 权益内容 |
| `broadband` | string | 宽带信息（文字描述） |
| `actual_price` / `baseFlow` / `voice_minutes` | string | 各省现网常用别名（广东等），可直接传，进入话术上下文 |
| 其他 | — | 任意自定义字段均可传入 |

> **比价提示**：如需启用「当前套餐 vs 推荐产品」自动比价（`{diff_str}` 与 `diff_table`），当前套餐与推荐产品请使用上表标注为**比价字段**的标准名（或其别名）。价格 / 流量 / 语音等只要能被识别，即可自动参与差异计算；识别规则见第 7 节。

#### 3.2.2 recommended_packages —— 产品列表（array，单 / 多产品统一入口）

数组，**单产品传 1 个元素，多产品传多个元素**。服务端按 `rank` 升序取 `topN` 个，**并发**逐产品各生成一条话术。每个产品对象字段：

**① 基础字段（内置多别名识别）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `offerId` | string | **强烈建议** | 产品 ID。响应 `recommend_results[].offerId`（及兼容字段 `product_id`）**原样回显此值**，供调用方关联产品；亦用于匹配话术模板 |
| `offerName` | string | 建议 | 产品名称（别名：`package_name` / `productName` / `name`）。当 `offerId` 无法命中模板时，服务端可用产品名做关键词回退匹配 |
| `initFee` | string/number | 建议 | 月费 / 实付价（元）（别名：`monthly_fee` / `price` / `fee`） |
| `offerFlow` | string/number | 否 | 套内流量（GB）（别名：`data_quota` / `dataGB` / `flow`） |
| `offerVoice` | string/number | 否 | 套内语音（分钟）（别名：`voice_quota` / `voiceMinutes` / `voice`） |
| `giftFlow` / `giftVoice` | string/number | 否 | 赠送流量（GB）/ 赠送语音（分钟） |
| `rank` | int | 否 | 推荐顺位，越小越优先；缺省按列表顺序 |
| `recommendation_reason` | string | 否 | 推荐理由，传入后话术会引用 |

**② 话术占位符扩展字段（可选，按模板占位符命名，直接进上下文填充）**

| 字段 | 说明 |
|---|---|
| `recommend_package_name` | 推荐套餐名称 |
| `recommend_original_price` | 推荐套餐原始价格（元） |
| `recommend_actual_price` | 推荐套餐实付价格（元 / 月） |
| `recommend_discount_amount` | 推荐套餐减免金额（元） |
| `recommend_base_flow` | 推荐套餐套内流量（GB） |
| `recommend_bonus_flow` | 推荐套餐赠送流量（GB） |
| `recommend_total_flow` | 推荐套餐总流量（GB，套内 + 赠送） |
| `recommend_voice_minutes` | 推荐套餐语音（分钟） |
| `recommend_preferential_period` | 推荐套餐优惠期（月） |
| `recommend_equity` / `recommend_broadband` | 权益 / 宽带 |
| `origPrice` / `discountPrice` / `privEndMonth` / `bandwidth` | 原价 / 优惠价 / 优惠截止月 / 带宽 |
| `diff` | 该产品与当前套餐差异（object），如 `{"diff_actual_price":"+21","base_flow_diff":"+15","bonus_flow_diff":"+10","voice_minutes_diff":"+100"}` |
| 其他 | 任意产品属性字段均可传入，字段名与模板占位符一致即自动填充 |

> **单产品与多产品完全同构**：产品放进 `recommended_packages` 数组即可，无论 1 个还是多个；不再区分「单产品对象」与「多产品数组」两种写法。
>
> **比价字段**：产品对象中的 `initFee`（价格）、`offerFlow`（流量）、`offerVoice`（语音）、`bandWidth`（宽带）、`suppCard`（副卡数）、`otherRight`（权益数组）会与 `current_package` 同名维度自动比价，产出 `{diff_str}` 与 `diff_table`（第 7 节）。若调用方已自行算好差异，也可用 `diff` 子对象直接传入固定差异值。

### 3.3 batch_contexts —— 话术生成上下文

控制「在哪个环节、哪个场景」生成话术。数组，支持 1~N 条；**不传或空数组**时按一条全空上下文处理（通用模板兜底）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product_id` | string | 否 | 产品标识（ID 或产品名关键词）。**为空 → 对 TopN 产品自动展开各生成一条**；非空 → 仅生成该产品话术 |
| `stage` | string | 否 | 环节，与模板「应用环节」对应，如 `个人市场` / `家庭市场` / `场景切入` / `营销挽留`。**字段名必须是 `stage`**，不要写成 `"个人市场": "个人市场"` |
| `scence` | string | 否 | 场景（**字段名固定为 `scence`**，不是 `scene`），如 `开口话术` / `近3个月流量超套` |
| `expand` | bool | 否 | 默认 `false`。为 `true` 且 `scence` 为空时，枚举该 `stage` 下所有场景，每场景各生成一条 |

> 多条目、多产品均并发处理，结果按序返回并回显 `stage/scence`。

**正确写法：**

```json
{ "product_id": "", "stage": "个人市场", "scence": "开口话术" }
```

**错误写法（`stage` 丢失，匹配精度下降）：**

```json
{ "product_id": "", "个人市场": "个人市场", "scence": "开口话术" }
```

## 4. 响应参数

### 4.1 响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务码：`200` 成功；`500` 服务内部异常 |
| `message` | string | 结果描述，成功为 `success` |
| `data` | object | 业务数据，结构见 4.2；异常时为 `null` |
| `other_info` | object/null | 直传模式恒为 `null` |

> **默认出参即上表全部字段**。`resource_context` / `metadata` / `api_calls` / `llm_prompts` 为运营测试排障字段，**不在对外规范内**；仅当请求带查询参数 `debug=1`（或 `true`/`yes`/`on`）时返回，现网对接请勿依赖。

### 4.2 data 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `callId` | string | 请求追踪 ID，原样回显 |
| `phone` | string | 用户手机号，原样回显 |
| `intent` | string | 业务意图，原样回显 |
| `province` | string | 省份代码，原样回显（入参原值；数字码如 `"200"` 亦原样回显） |
| `recommend_results` | array | 话术结果列表，每项一个「产品 × 环节 × 场景」 |

**recommend_results 项字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `stage` | string | 环节回显，**仅批量模式**（传了 `batch_contexts`）返回 |
| `scence` | string | 场景回显，**仅批量模式**返回 |
| `product_id` | string | **兼容关联键**：有推荐产品时回显入参 `offerId`（与 `offerId` 字段同值）；旧单产品无 `offerId` 时可能回显业务类型 / 产品名；通用兜底且无产品时为空串 |
| `offerId` | string | **产品关联键（推荐使用）**：原样回显入参产品的 `offerId`；占位 / 无产品时为空串 |
| `rank` | int | 推荐顺位（与入参产品 `rank` / 展开顺序一致） |
| `marketing_text` | string | **生成的话术正文**，口语化、无前缀，可直接播报 |
| `diff_table` | object/null | **比价表**（当前产品 vs 推荐产品），结构见第 7 节；服务端模板启用比价时返回，否则 `null` |

> **关联规则**：多产品场景下，优先用 `recommend_results[i].offerId`（= 入参 `recommended_packages[j].offerId`）把话术关联回产品；`product_id` 同步回显同一值以兼容旧对接。勿用话术正文或产品名做关联。

### 4.3 错误码

| HTTP | 响应体 | 触发条件 | 处理建议 |
|---|---|---|---|
| 200 | `{"code":200,"message":"success","data":{...}}` | 成功（个别话术降级仍返回 200） | 正常解析 |
| 404 | `{"detail":"未找到技能包: province=xx intent=xx"}` | `province+intent` 未发布 | 核对附录 A，联系服务端发布 |
| 422 | FastAPI 参数校验结构 | 缺必填 / `topN` 超 1~10 / 类型错误 | 按提示修正入参 |
| 500 | `{"code":500,"message":"<错误详情>","data":null}` | 服务内部异常 | 携带 `callId` 联系服务端排查 |

> 个别产品话术生成失败时自动降级为通用引导话术，整体仍返回 200，调用方无需特殊处理。

## 6. 占位符填充规则

话术模板中的占位符由大模型依据 `extra_info` 传入字段**按字段名语义自动填充**，调用方只需保证「字段名与占位符名一致」：

| 形态 | 示例 | 填充规则 |
|---|---|---|
| `[字段名]` 方括号 | `[lastedMonth]`、`[flow+giftFlow]` | 按字段名取值，支持算术组合（只传基础字段，组合值自动计算） |
| `**（字段名）` 星号 | `**（recommend_actual_price）` | `**` 为取值位置，括号内为字段注释，按名替换 |
| `{关联变量}` 花括号 | `{pkg_brief}`、`{diff_str}` | 系统按标准域自动格式化注入 |

**保障规则**：缺失或为 0 的字段自动跳过、不臆造；同名字段就近对应、不串填；未匹配数据的占位符改写为通顺口语。

**命名建议**：数值不带单位（如 `"initFee":"59"` 而非 `"59元"`）；流量统一 GB、语音统一分钟、金额统一元；下游推荐引擎 → `extra_info` → 模板占位符全链路同名。

## 7. 比价 / 差异对比功能

服务端将 `current_package`（当前产品）与每个 `recommended_packages[i]`（推荐产品）逐维度比对，产出：

- **比价话术** `{diff_str}`：单行差异摘要注入话术，如「月费+30元，流量+20GB，语音-30分钟」；
- **比价表** `diff_table`：结构化对比表，随对应产品的 `recommend_results` 项返回（见 5.4 / 4.2）。

### 7.1 参与比价的字段（多别名自动识别）

当前产品与推荐产品使用下列任一别名即可被识别为同一比价维度，**单位需统一**：

| 比价维度 | 可识别字段名（别名，任填其一） | 单位 |
|---|---|---|
| 价格 | `initFee` / `monthly_fee` / `fee` / `price` / `curOfferFee` | 元 / 月 |
| 流量 | `offerFlow` / `data_quota` / `flow` / `data` / `flowGb` | GB（>200 视为 MB 自动换算） |
| 语音 | `offerVoice` / `voice_quota` / `voice` / `minutes` / `minute` | 分钟 |
| 宽带 | `bandWidth` / `bandwidth` / `broadband_speed` | M（仅推荐产品有则记「新增」） |
| 副卡 | `suppCard` / `supp_card` / `subCard` | 张 |
| 其他权益 | `otherRight`（字符串数组，仅推荐产品侧） | — |

> 价格支持分 / 元自动归一（值 > 1000 视为「分」自动 ÷100）；流量 > 200 且无「G」标识时视为「MB」自动 ÷1024。**建议直接传规范单位（元 / GB / 分钟）避免歧义。**

### 7.2 diff_table 结构

```json
{
  "headers": ["项目", "当前产品", "目标产品", "差异"],
  "rows": [
    { "label": "产品名",     "current": "当前套餐名", "target": "推荐套餐名", "diff": "" },
    { "label": "价格(元/月)", "current": 99,          "target": 129,         "diff": "+30元" },
    { "label": "流量",       "current": "30GB",      "target": "50GB",      "diff": "+20GB" },
    { "label": "语音(分钟)",  "current": 200,         "target": 170,         "diff": "-30分钟" }
  ]
}
```

- `rows` 按「产品名 / 价格 / 流量 / 语音」固定顺序输出，并在有数据时动态追加「宽带 / 副卡 / 其他权益」行；
- `diff` 为带方向的差值标签：`+N单位`（升）/ `-N单位`（降）/ `持平`；某侧字段缺失时该行 `current`/`target` 显示 `—`、该维度不计入比价话术。

### 7.3 三种比价用法

| 方式 | 入参做法 | 产出 |
|---|---|---|
| 自动比价（推荐） | `current_package` 与产品对象都用 7.1 规范比价字段 | `{diff_str}` 比价话术 + `diff_table` 比价表（模板启用时） |
| 调用方自算差异 | 在产品对象内传 `diff` 子对象（如 `{"diff_actual_price":"+21",...}`） | 差异值作为占位符进入话术，不自动生成 `diff_table` |
| 不比价 | 不传 `current_package` 或产品缺比价字段 | 仅生成推荐话术，`diff_table=null` |

> `diff_table` 是否随响应返回由服务端对应省份 / 意图的模板配置决定（模板启用比价表变量时输出）。如需为某省份 / 意图开启比价表，请联系服务端在模板配置，**本接口入参与字段无需改动**。

## 8. 多产品生成与模板匹配说明

### 8.1 展开与并发

| 入参条件 | 服务端行为 |
|---|---|
| `recommended_packages` 有 N 个元素，`topN=M`，`batch_contexts[].product_id=""` | 取前 `min(N,M)` 个产品，**并发**各生成 1 条话术，一次返回 |
| `batch_contexts[].product_id` 非空 | 仅生成该产品 1 条（不展开列表） |
| 仅旧版 `final_recommendations` 对象、无 `recommended_packages` | 行为与改动前一致，通常生成 1 条；**不影响多产品路径** |

**并发上限配置**（服务端）：全局文件 `config/concurrency.json` → `llm_max_concurrency`，**默认 8**。覆盖优先级：`biz_config.strategy.llm_max_concurrency` > 环境变量 `ZNHS_LLM_MAX_CONCURRENCY` > `concurrency.json`。下游对接无需传此字段。

### 8.2 话术模板匹配与响应关联（解耦）

多产品与单产品共用同一套匹配维度：`batch_contexts.product_id` + `stage` + `scence`。

| 用途 | 取值 | 说明 |
|---|---|---|
| **响应关联键** | 产品 `offerId` | 写入 `recommend_results[].offerId`（及兼容字段 `product_id`），供调用方关联产品 |
| **模板匹配键** | ① `batch_contexts.product_id`（若非空）→ ② `offerId` → ③ `offerName` / `recommend_package_name` | 与单产品一致；兼容「模板按产品名关键词配置」的省份（如广东） |
| **产品定位** | `batch_contexts.product_id` 从 `recommended_packages` 取产品 | 支持 offerId 精确 / 完整产品名精确 / 关键词模糊（如 `"流量"` ↔ 产品名含「流量」） |

| `batch_contexts.product_id` | 有 `recommended_packages` 时 | 无推荐列表（旧单产品）时 |
|---|---|---|
| 空串 `""` | 对 TopN 产品各生成 1 条；模板按产品名（`offerName`）关键词匹配 | 按 `stage`/`scence` 走通用模板，生成 1 条 |
| 非空（业务类型 / 关键词 / 名称） | **仍展开 TopN 各 1 条**；`product_id` **只作业务类型**优先匹配话术模板；响应 `offerId` / `product_id` **回显产品 offerId** | 按该值匹配模板，生成 1 条；响应 `offerId` 通常为空 |

> 若希望某 `offerId` 走专属话术，在服务端模板的 `product_id` 中直接配置该 `offerId` 即可优先精确命中。  
> `batch_contexts.stage` / `scence` 请按第 3.3 节正确传字段名，可提高匹配精度。

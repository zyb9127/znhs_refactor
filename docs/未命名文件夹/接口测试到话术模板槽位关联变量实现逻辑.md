# 接口测试 → 话术模板槽位 关联变量实现逻辑

> 配套优化点：Skill 管理页 `SkillConfigEditor` 与 `TemplateEditDialog` 的交互改造，实现"接口编辑 → 话术模板编辑"的清晰映射与勾选，闭环 context 工程。

---

## 一、整体数据链路

```
 ┌──────────────┐  response_extract   ┌──────────────────┐  field_transform  ┌──────────────────────┐
 │  接口原始响应 │ ───────────────▶ │  raw_*  中间槽位  │ ─────────────▶ │  resource_context     │
 └──────────────┘                   └──────────────────┘                  │ (7 大标准域)          │
                                                                          └──────────┬───────────┘
                                                                                     │ linked_vars
                                                                                     ▼
                                                                          ┌──────────────────────┐
                                                                          │  Prompt 拼装 → LLM    │
                                                                          └──────────────────────┘
```

7 大标准域（`core/context.py` 与 `数据映射域.txt` 对齐）：

| key                    | 含义                                       |
| ---------------------- | ------------------------------------------ |
| `current_package`      | 用户当前套餐                               |
| `usage`                | 历史用量                                   |
| `tags`                 | 用户标签                                   |
| `user_info`            | 用户基础信息                               |
| `recommended_packages` | 推荐套餐                                   |
| `user_profile`         | 用户画像                                   |
| `domain_ext`           | 扩展域（家庭、合约、订购等）                |

## 二、模板侧 `linked_vars` ↔ 标准域映射

`steps/script_step.py` 中 `_VAR_LABELS` 决定 Prompt 行；前端按下表勾选即可：

| linked_var key  | 中文名         | 取值来源（slot）                  |
| --------------- | -------------- | --------------------------------- |
| `cur_brief`     | 当前套餐信息   | `current_package`                 |
| `pkg_brief`     | 推荐产品信息   | `recommended_packages[0]`         |
| `diff_str`      | 套餐差异       | 由 `PackageDiff` 自动计算         |
| `usage_line`    | 历史用量       | `usage`                           |
| `user_tags`     | 用户标签       | `tags`                            |
| `user_info`     | 用户基础信息   | `user_info`                       |
| `user_profile`  | 用户画像       | `user_profile`                    |
| `domain_ext`    | 扩展信息       | `domain_ext`                      |
| `extra_info`    | 主服务补充信息 | 主服务 `extra_info` 透传         |
| `extra_context` | 模板匹配上下文 | 主服务 `extra_context` 透传      |
| `table`         | 差异表格       | 仅前端展示，**不进 LLM**          |

## 三、模板侧 `linked_apis` 的运行时语义

- **未勾选**：兼容旧版本，调用本 skill 下全部 `enabled=true` 的接口；
- **勾选 N 个**：运行时仅触发该 N 个接口（DataStep 并发），减少 RT 与外呼成本。

## 四、接口侧"产出哪些标准域"的判定规则

前端 `inferProducedSlots(cfg)`：

1. 取 `field_transform` 顶层 key（如 `usage`、`tags`），属于 7 大域之一即视为产出该域；
2. 未配置 `field_transform` 时，回退到 `response_extract` 的同名 key（自动透传场景）。

## 五、UI 层的"清晰映射 + 勾选"

### `TemplateEditDialog.vue`
- ① **关联接口卡片**：勾选接口的同时，下方以 tag 形式展示该接口产出的标准域（`success` 表示已被某个 linked_var 引用）；
- ② **模板内容**：识别 `{var}` 占位符，与 `linked_vars` 不一致时给出橙色提醒；
- ③ **关联变量网格**：
  - `supplied`（绿色左条）：已勾接口能提供该 slot；
  - `missing`（红色背景）：勾了变量但接口未提供 → 必有占位符空缺；
  - `辅助`：无需接口（如 `extra_info`、`table`）。
- ④ **自动推荐按钮**：根据已勾接口产出的 slot 反向勾选对应 `linked_vars`；
- ⑤ **Prompt 实时预览**：按 `_build_prompt` 真实顺序渲染，缺接口的 slot 显示 `<⚠ 未配置接口提供 xxx>`，所见即所得。

### `SkillConfigEditor.vue`
- 接口表新增 **"被引用 N 个模板"** 列；
- 模板表新增 **"关联接口"** 列；
- 新增 **"数据流映射" Tab**：四张 KPI 卡（接口数 / 模板数 / 覆盖标准域 / 未闭环模板）+ 三列流程图（接口 → 标准域 → 模板）+ 详细映射矩阵表，一眼看出 context 是否闭环。

## 六、与运行时的对齐保证

- 前端的 `STANDARD_SLOTS`、`VAR_KEY_TO_SLOT` 与后端 `core/context.py` 的 `STANDARD_SLOTS` / `steps/script_step.py` 的 `_VAR_LABELS` 一一对应；任一处新增标准域时需同步修改三处。
- 模板保存时 `linked_apis`、`linked_vars` 直接写入 `script_templates_v2[*]`，运行链路无需额外解析。

# 降档挽留话术 · 技术与接口文档（小挽能力迁移至营销话术智能体）

| 文档版本 | 日期 | 说明 |
|---|---|---|
| v1.0 | 2026-09-03 | 首版。将「小挽机器人」降档挽留能力迁移到营销话术智能体**透传模式标准接口**，供各分中心自助配置接口与挽留话术。含入参/出参样例、分中心配置指南、差距与迁移路线。 |

---

## 1. 背景与目标

小挽机器人（`api_server_znhs-new.py` + `parse_prompt_fj.py`）当前独立承载各省"降档挽留话术"：一次请求携带多个降档原因（`reasonsForDown`），每个原因带独立画像（`customInfo[原因]`），按 `botName + actionType + 原因` 选模板，逐原因生成挽留话术。

目标：把这套能力**迁移到营销话术智能体**，用其**透传模式标准接口**承载，让各分中心在配置页自助完成「接口 + 挽留话术」配置，不再为每省单独改代码。

结论：**契合度高，可直接承载**。核心机制天然对齐——

| 小挽机制 | 营销话术机制 |
|---|---|
| 一次请求多个降档原因，逐原因各出话术 | 多产品/多条批量，逐单元各生成一条 |
| 每个原因独立 `customInfo` | 逐单元用自己那份字段填槽（`{pkg_brief[字段]}` 子字段隔离，不串填） |
| 「挽留」 | 原生 `stage=挽留` 环节（回调对应 `aiRetentionMarketingDesc`） |
| `botName+actionType+原因` 选模板 | 产品 + 环节 + 场景 12 档模板匹配 |
| 空参走固定话术 | 通用兜底模板 + `话术要求` 原样输出 |

**唯一需要注意的差异**：透传模式**不做套餐维表 join**（小挽在服务端用 `masterPackageId`→维表→"当前/目标套餐"）。对比类场景需：①调用方侧先查维表、把解析好的套餐字段直传；或②给技能包配真实接口节点走"接口查询模式"回调省份套餐维表。纯挽留类（资费贵/流量用不完/网龄）不涉及维表，直接可用。

## 2. 概念映射（小挽 → 营销话术透传模式）

| 小挽字段 | 营销话术入参 | 映射建议 |
|---|---|---|
| `botName`（省份专席） | `province` | `zhejiangzx_bot`→`zhejiang`、`beijingzx_bot`→`beijing`（兼容数字码，如 `571`→`zhejiang`） |
| 固定"降档挽留"能力 | `intent` | 每省建一个技能包 `intent="降档挽留"` |
| `actionType`（环节） | `batch_contexts.stage` | 统一 `挽留`；如需区分登记/对比可用不同 stage |
| `reasonsForDown[]`（降档原因） | 每个原因 = `extra_info.recommended_packages` 里一个条目，`product_id`=原因名 | 逐原因各出一条挽留话术 |
| `customInfo[原因]`（逐意图画像） | 该条目自带字段（`{pkg_brief[字段]}` 引用）+ 共享的 `current_package`/`usage` | 逐单元隔离，不串填 |
| 原因下的子场景（福建"一个月/多月超套"） | `batch_contexts.scence` | 覆盖小挽第四层子模板 |
| `topN` | `topN` | 一致 |
| `userId` / `msgId` | `phone` / `callId` | 用户标识 / 追踪回显 |
| `answer[原因]` | `recommend_results[].product_id`（回显原因） | 调用方按回显重组 |
| 套餐对比表 | `diff_table`（系统按 当前 vs 条目 自动算） + `{diff_str}` | 结构化返回，前端渲染 |

**关键设计**：把每个"降档原因"建模成 `recommended_packages` 的一个条目，`product_id`=原因名。这样①逐原因用营销话术的"多产品逐条生成"能力各出一条话术；②原因专属画像放在条目里，靠 `{pkg_brief[字段]}` 逐单元隔离取值，天然复刻小挽 `customInfo[原因]` 的隔离语义。

## 3. 接口定义

| 项 | 内容 |
|---|---|
| 接口地址 | `POST {host}/znhs/marketing/recommend` |
| 请求格式 | `Content-Type: application/json; charset=utf-8` |
| 响应格式 | `application/json; charset=utf-8` |
| 鉴权 | 无（内网服务，网络层隔离） |
| 建议超时 | 15 秒（多原因并发生成，典型 2~8 秒） |

### 3.1 顶层入参

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `phone` | string | 是 | — | 用户手机号（对应小挽 `userId`），标识与日志追踪 |
| `intent` | string | 是 | — | 固定 `降档挽留`（需与技能包发布名一致） |
| `province` | string | 是 | — | 省份代码（小写英文），如 `zhejiang`；兼容数字码 `571` |
| `topN` | int | 否 | 3 | 生成上限；降档原因数即为条目数，`topN` 取 ≥ 原因数 |
| `callId` | string | 否 | 服务端生成 | 追踪 ID（对应小挽 `msgId`），响应原样回显 |
| `extra_data` | object | 否 | `{}` | 透传模式传空对象 |
| `extra_info` | object | 否 | `{}` | **直传主体**：用户信息 + 降档原因条目，见 3.2 |
| `batch_contexts` | array | 否 | `[]` | 生成上下文（环节/场景），降档挽留固定 `stage=挽留`，见 3.3 |

### 3.2 extra_info（直传主体）

| 键 | 类型 | 说明 |
|---|---|---|
| `current_package` | object | 用户当前套餐（对比/挽留话术引用），如 `package_name`/`actual_price`/`baseFlow`/`voice_minutes` |
| `usage` | object | 历史用量，建议三层：`data_usage`/`voice_usage`/`consumption` |
| `user_info` | object | 用户基础信息，如 `internetAge`（网龄/年） |
| `recommended_packages` | array | **降档原因条目数组**：每个元素一个降档原因。约定字段见下表 |

**recommended_packages 元素（= 一个降档原因）：**

| 字段 | 必填 | 说明 |
|---|---|---|
| `product_id` | 是 | **降档原因名**（如 `现有资费太贵`），模板据此匹配该原因的挽留模板；结果回显于此 |
| `rank` | 否 | 顺位（1..N），按原因优先级排序 |
| `<原因专属画像字段>` | 否 | 小挽 `customInfo[原因]` 里的字段，如 `top5Business`、`netAge`；模板用 `{pkg_brief[字段]}` 引用 |
| 目标套餐字段（对比场景） | 否 | `offerName`/`initFee`/`offerFlow`/`offerVoice` 等；配合 `current_package` 由系统自动算 `{diff_str}`/`diff_table` |

> 纯挽留原因（资费贵/流量用不完/网龄）条目可只有 `product_id` + 少量专属字段；对比原因条目带目标套餐字段。

### 3.3 batch_contexts

降档挽留统一传一条：`{ "product_id": "", "stage": "挽留" }`。`product_id` 为空 → 对 `recommended_packages` 里全部原因各生成一条 `挽留` 话术。对比场景可加 `scence`（如 `套餐比较口径`）以命中更精确的模板。

## 4. 出参

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 200 成功；404 技能包未发布；422 参数错误；500 内部异常 |
| `message` | string | `success` 或错误详情 |
| `data.callId` / `data.phone` / `data.intent` / `data.province` | — | 原样回显 |
| `data.recommend_results` | array | 逐原因话术结果 |

**recommend_results 项：**

| 字段 | 说明 |
|---|---|
| `product_id` | **降档原因名**（回显），调用方据此重组 `answer[原因]` |
| `rank` | 顺位 |
| `marketing_text` | 生成的挽留话术正文（口语化，可直接供坐席） |
| `diff_table` | 对比场景返回结构化差异表；否则 `null` |
| `stage` / `scence` | 环节/场景回显（批量模式） |

## 6. 分中心配置指南（自助）

在配置页按三步完成即可，无需服务端改代码：

### 6.1 建技能包

`province`（如 `zhejiang`）+ `intent=降档挽留`。

### 6.2 配接口（透传模式）

接口节点：`source_type=direct`、`direct_mode=passthrough`；`mock_response` 粘贴 5.1 的 `extra_info` 样例（含 `recommended_packages` 原因条目）。透传字段勾选 `current_package`/`usage`/`user_info`/`recommended_packages` 及其下产品字段（`product_id`、`top5Business`、`netAge`、`offerName`…；嵌套字典字段已支持展开选取）。

### 6.3 配挽留话术模板

按"降档原因"各建一条模板：

| 配置项 | 取值 |
|---|---|
| 应用环节 | `挽留` |
| 模板匹配 · 产品ID | 原因名（如 `现有资费太贵`）；支持逗号/换行配多个关键词，与入参互为子串即命中 |
| 模板内容 | 占位符：`{current_package[package_name]}`、`{pkg_brief[top5Business]}`、`{pkg_brief[netAge]}`、`{pkg_brief[offerName]}`、`{diff_str}`、`{usage_line}` 等 |
| 话术要求 | 沿用小挽挽留指令：移动降档挽留客服、≤100 字、说服不降档、不含资费金额、缺字段按 ** 保留、无欢迎语；对比场景加"差异按(目标-当前)口径，减少了就明确指出以突出当前优势" |

另建一条 `产品ID 为空` 的**通用兜底模板**（`应用环节=挽留`）承接空参/未命中原因。

### 6.4 占位符对照（降档挽留常用）

| 占位符 | 来源 | 说明 |
|---|---|---|
| `{current_package[package_name]}` | `extra_info.current_package` | 当前套餐名 |
| `{cur_brief}` | 当前套餐域格式化 | 当前套餐摘要 |
| `{pkg_brief[<字段>]}` | 当前原因条目 | 原因专属字段（`top5Business`/`netAge`/`offerName`…），**逐原因隔离** |
| `{usage_line}` / `{usage}` | `extra_info.usage` | 历史用量摘要 |
| `{diff_str}` | 系统计算 | 当前套餐 vs 目标条目差异（对比场景） |
| `{user_info}` | `extra_info.user_info` | 用户基础信息 |

## 7. 差距与迁移路线

| 事项 | 现状 | 迁移做法 |
|---|---|---|
| 套餐维表 join | 透传模式不做 | 调用方侧先查维表直传解析后字段；或给技能包配真实接口节点走接口查询模式回调省份套餐维表 |
| 每原因多条话术（topN>1） | 每单元默认 1 条 | 调采样温度或多次请求；挽留通常 1 条足够 |
| HTML 对比表 | 产出 `diff_table` 结构化数据 | 前端自行渲染表格 |
| 空参固定话术 | 有通用兜底 | 配一条 `产品ID 为空` 的固定内容模板（话术要求=原样输出/温和挽留） |
| `answer` 按意图组织 | 返回 `recommend_results[]` 带 `product_id` | 调用方按 `product_id`(原因) 重组 |
| 广东 `$` 分隔意图、内蒙 `{variable}` | 特殊语法 | 拆成独立原因条目 + 模板占位符 |

**推荐迁移节奏**：

1. **纯挽留类**（`actionType=1`：资费贵/流量用不完/网龄，无维表依赖）——分中心当天可配通；
2. **对比类**（`actionType=2/3`：需维表预处理或接口节点）；
3. **特殊省**（广东全球通、内蒙代客降档）。

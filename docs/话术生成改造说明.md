# 话术生成链路改造说明

本文记录话术生成链路的确定性改造，供后续维护、配置迁移和问题排查使用。

## 本轮四次提交归纳

最近四次提交可以合并为一条完整改造链路：

1. `8e9ca44`：建立模板驱动的确定性出稿链路；补充多场景模板按派生字段选择、`array_find` 比较运算与 `all/any` 匹配、`timeType` 排序和空值保护，并同步 Schema、前端配置和测试。
2. `dd708ae`：残留占位符支持数字开头的字段名，例如 `{3MonthsOutFlowFee}`。

4. `9ca8ef5`：完善二次表达改写的事实保护；真实事实、数字和未知占位符分别使用保护标记，同值多次出现按位置独立保护，并同步山东模板的 `{}` 占位符、`linked_vars` 和测试用例。

因此，本说明中的“确定性模板出稿”“花括号占位符识别”和“后置表达改写保护”属于同一条链路，不应分别实现或重复维护。

## 1. 总体目标

话术生成链路调整为：

```text
接口取数
  ↓
派生字段计算
  ↓
根据派生字段选择模板场景
  ↓
严格按照模板填充事实
  ↓
默认直接输出模板结果
  ↓
只有显式配置采样温度时，才进行二次表达改写
```

核心原则：

> 大模型不负责判断业务场景、不负责选择产品、不负责修改事实。
> 业务判断由派生字段和模板配置完成，大模型最多只做表达方式调整。

## 2. 模板确定性渲染与空槽位处理

相关文件：

- `steps/script_step.py`
- `engine/prompt_builder.py`
- `schemas/biz_config.schema.json`
- `tests/test_slot_fallback.py`

### 2.1 严格按照模板生成

当模板存在 `template_content` 时：

1. 以模板原文作为基础话术；
2. 只替换模板中明确写出的占位符；
3. 只使用已经计算出的真实字段；
4. 模板中没有的事实，禁止从上下文自行添加；
5. 不允许模型自行补充价格、流量、权益、产品编码等内容；
6. 数值为 `0` 时必须照实填入，不能当成空值；
7. 模板固定文字不由模型自行改写。

例如模板是：

```text
套餐包含{flow}GB流量，月费{price}元。
```

上下文是：

```json
{
  "flow": 30,
  "price": 59
}
```

确定性渲染结果是：

```text
套餐包含30GB流量，月费59元。
```

模型不能擅自增加“高速”“非常划算”等模板中没有的事实或营销结论。

### 2.2 `**` 掩码与缺失数据

默认情况下，以下两种输入必须完全等价：

```json
{}
```

```json
{
  "price": "**"
}
```

也就是说，字段未传和字段传入 `**` 都表示没有真实数据。

系统不会把 `price=**` 当作真实事实发送给模型，避免模型照读 `**` 或拿上下文中的其他数字错误填充。

默认配置口径为 `passthrough`：

```json
{
  "slot_fallback": {
    "mode": "passthrough",
    "placeholder": "**"
  }
}
```

行为如下：

```text
字段有真实值       → 原样填充
字段缺失或为 **    → 保留原句，位置填 **
```

例如：

```text
模板：月费{price}元，包含{flow}GB流量。
数据：price=**，flow=30
结果：月费**元，包含30GB流量。
```

`**` 只在字段值完整等于掩码时生效：

```text
price = "**"       → 缺失
price = "  **  "   → 缺失
```

普通文本中的星号不会被误删，例如：

```text
商品描述 = "限时**特惠**"
```

### 2.3 零值必须保留

以下值都是真实数据，不能当成空值：

```text
0
"0"
0.0
"0.0"
```

例如：

```text
模板：套餐含语音{voice}分钟。
数据：voice=0
结果：套餐含语音0分钟。
```

不能改成 `**`，也不能因为是 `0` 删除整句。

### 2.4 残留占位符处理

模型输出或模板渲染后，还会进行确定性后处理：

```text
有映射事实       → 强制填入真实值
无映射事实       → 按 slot_fallback 处理
```

默认 `passthrough` 模式下：

```text
残留 {字段} → 替换成 **
```

如果技能包配置：

```json
{
  "slot_fallback": {
    "mode": "drop"
  }
}
```

则会删除包含空槽位的整个子句。例如：

```text
模板：您好，月费{price}元，包含30GB流量。
结果：您好，包含30GB流量。
```

`drop` 是兼容旧逻辑的按技能包开关，默认仍使用 `passthrough`。

### 2.5 残留占位符统一按花括号识别

残留占位符不再要求字段名必须以字母或下划线开头，而是统一识别为“单层花括号包裹的内容”：

```text
{price}
{3MonthsOutFlowFee}
{current_package[curOfferDesc]}
{用户标签.星级}
```

这样可以覆盖数字开头、点号、中文字段名以及域内子字段等配置写法。只要模板或模型输出中仍残留 `{...}`，后处理就会按空槽位规则处理，不会把它带到最终话术中。

山东模板已统一使用 `{字段名}` 形式；旧的 `[字段名]` 写法不会被当作运行时占位符，应在配置迁移时一并转换。

### 2.6 自定义掩码

可以通过 `treat_as_empty` 增加其他缺失标记：

```json
{
  "slot_fallback": {
    "mode": "passthrough",
    "placeholder": "＿＿",
    "treat_as_empty": ["**", "-", "无", "N/A"]
  }
}
```

这些值都会被视为无真实数据，最终按缺失槽位处理。

## 3. 按派生字段选择模板场景

相关文件：

- `steps/script_step.py`
- `skills-runtime/tianjin/营销活动/config/biz_config.json`
- `tests/test_slot_fallback.py`

### 3.1 正确处理链路

先计算派生字段：

```text
超套费用合计 = 0.5
推荐场景 = 场景一
```

再从多场景模板中精确选择：

```text
推荐场景 = 场景一
  ↓
只截取“场景一：……”这一段
```

业务场景和产品编码不再交给大模型判断。

### 3.2 场景名称不写死

代码不再固定识别“场景一”“场景二”“兜底场景”等名称。

模板中独立成行、以冒号结尾的标签都可以作为场景标签：

```text
高流量客户：推荐大流量产品。
低活跃客户：推荐基础产品。
暂不推荐：先保持当前套餐。
```

如果派生字段得到：

```text
推荐场景 = 暂不推荐
```

则只输出：

```text
先保持当前套餐。
```

实现方式是读取派生字段的实际值，与模板标签做精确匹配，不维护固定场景白名单。

### 3.3 场景匹配失败

以下情况都视为没有可用场景：

- 没有 `推荐场景`；
- 派生值为空；
- 派生值在模板中找不到对应标签。

此时不会随便选择一个场景，也不会输出多段业务编码。

处理链路为：

```text
严格模板场景匹配失败
  ↓
返回空字符串
  ↓
进入通用确定性兜底话术 _fallback_text()
```

如果根本没有命中模板，则继续沿用原有的无模板 / fallback Prompt 生成路径。

## 4. 后置采样与表达改写

相关文件：

- `steps/script_step.py`
- `schemas/biz_config.schema.json`
- `frontend/src/pages/AutoConfig/components/SkillConfigEditor.vue`

### 4.1 采样温度不参与首次生成

新的调用顺序是：

```text
严格模板渲染出基础话术
  ↓
script_temperature > 0？
  ├─ 否：直接返回基础话术
  └─ 是：调用第二次模型，只调整表达方式
```

默认值为：

```text
script_temperature = 0
```

未显式配置时，不会发生第二次模型调用，也不会增加接口响应时间。

只有业务配置显式写入大于 `0` 的值时，才启用后置改写：

```json
{
  "strategy": {
    "script_temperature": 0.8
  }
}
```

### 4.2 后置改写约束

第二次模型调用只接收第一次生成的基础话术，不注入用户上下文。

允许：

- 调整措辞；
- 调整语序；
- 调整连接词；
- 调整口语表达。

禁止：

- 新增、删除或推断产品事实；
- 修改产品、价格、流量、权益、时间、业务编码；
- 新增数字；
- 根据上下文扩写内容。

改写前会把基础话术中的内容替换成按出现位置分配的保护标记：

```text
真实槽位事实：__ZNHS_FACT_A__
数字事实：    __ZNHS_NUM_B__
未传入槽位：  __ZNHS_SLOT_C__
```

相同内容的多次出现也会分别分配标记，不能把三个相同的 `**` 合并成一个标记。改写后检查：

1. 保护标记是否完整；
2. 保护标记出现次数是否一致；
3. 是否出现新的数字；
4. 是否仍然是有效中文话术。

校验失败时回退到第一次生成的基础话术。

### 4.3 未传参数时的事实边界

未传参数或参数值为 `**` 时，`**` 表示“事实未知”，不是可由模型补全的自然语言。二次改写仍然可以调整周围的措辞，但必须保留占位符本身：

```text
基础话术：我看您**月流量用超**元啦，咱超出后**元/G。
允许改写：我看您**月流量超出**元了，超出后按**元/G计算。
禁止改写：我看您这个月流量超出99元了……
```

如果模型把 `**月` 改成“这个月”、删除未知价格，或用具体数字替代未知槽位，事实保护校验必须失败并回退基础话术。这样既保留了二次表达改写能力，也不会把缺失数据变成模型猜测。

### 4.4 温度含义

```text
0     = 不进行二次改写，原文输出
0.5   = 较保守地调整表达
0.8   = 中等随机性
越高  = 表达变化越随机
```

如果要求和模板完全一致，应使用：

```text
script_temperature = 0
```

## 5. 派生字段逻辑

相关文件：

- `plugins/derived_fields.py`
- `schemas/api_nodes.schema.json`
- `frontend/src/pages/AutoConfig/components/SkillConfigEditor.vue`
- `tests/test_derived_fields.py`

### 5.1 `array_find` 数组筛选

```json
{
  "type": "array_find",
  "from": "userinfo_json",
  "where": {
    "timeType": "0"
  }
}
```

表示从 `userinfo_json` 中找到 `timeType=0` 的记录，并返回整条记录。

### 5.2 支持比较运算符

```json
{
  "type": "array_find",
  "from": "userinfo_json",
  "where": {
    "over_flow_fee": {
      "gt": 0
    }
  }
}
```

支持：

```text
eq / ne / gt / gte / lt / lte
```

裸值仍然表示精确匹配：

```json
{
  "timeType": "0"
}
```

等价于：

```json
{
  "timeType": {
    "eq": "0"
  }
}
```

### 5.3 支持 `all` 和 `any`

默认是 `all`，即所有条件都满足：

```json
{
  "type": "array_find",
  "from": "userinfo_json",
  "match": "all",
  "where": {
    "over_flow_fee": {"gt": 0},
    "over_voice_fee": {"gt": 0}
  }
}
```

使用 `any` 时，任意条件满足即可：

```json
{
  "type": "array_find",
  "from": "userinfo_json",
  "match": "any",
  "where": {
    "over_flow_fee": {"gt": 0},
    "over_voice_fee": {"gt": 0}
  }
}
```

### 5.4 `timeType` 排序与空值保护

数组元素包含 `timeType` 时，会先按数值升序排序：

```text
0 = 当月
1 = 上月
2 = 上上月
```

然后取第一条符合条件的记录。

派生字段不会把缺失数据伪造成 `0`：

```text
没有数据              → 不产出该派生字段
sum 没有任何有效值    → 返回 None
比较遇到空值         → 判定为不满足
```

这样可以避免“没有超套数据”被误判为“超套费用为 0”，从而错误路由到营销场景。

派生字段按 JSON 声明顺序计算，后面的字段可以引用前面已经计算出的派生字段。

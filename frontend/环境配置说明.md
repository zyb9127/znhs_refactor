# 前端环境配置说明

## 📋 环境概览

项目现已配置三个独立的运行环境，每个环境有独立的 `.env` 文件和构建命令。

## 运行形态与主应用接入

| 环境 | 是否接入真实灵运主应用 | 无界子应用标识 | 是否必须有用户 `id` 才显示页面壳层 |
|------|------------------------|----------------|-------------------------------------|
| **本地开发** | 否（本地起 Vite 或 `main.py` 直连浏览器即可测页） | 无 `window.__POWERED_BY_WUJIE__` | **否**：按本地 SPA 测，`App.vue` 会直接渲染 |
| **灰度 / 生产** | 是（正式挂在主应用内） | 有 `window.__POWERED_BY_WUJIE__` | **是**：需主应用注入登录态（`userInfo.id`），与灵运嵌入一致 |

补充说明：

- **本地**：不接主应用时，浏览器里不会出现无界子应用标记，管理页不要求灵运用户上下文，便于接口与页面联调。
- **灰度 / 生产**：构建产物由主应用按 `subAppList` 等配置加载；子应用内需主应用下发用户信息，行为以接入侧为准。

实现上可见 `src/App.vue` 中 `showAppShell`：非无界直连时恒为展示；仅无界内才依赖 `userInfo.id`。

### 接口路径（开发 / 灰度 / 生产）

业务页统一通过 `src/utils/apiUrl.js` 的 **`apiUrl()`** 拼接请求地址：

| 场景 | 行为 |
|------|------|
| **本地 `npm run dev`** | 仍请求 **`/api/...`**，由 Vite `proxy` 转到后端 **`/znhs/api/...`** |
| **生产构建**（`VITE_API_URL_PREFIX` 为空） | 使用 **`import.meta.env.BASE_URL`**（一般为 **`/znhs/`**），即 **`/znhs/api/...`**，与 FastAPI 挂载方式一致 |
| **灰度构建** | `VITE_API_URL_PREFIX=/znhs` 时请求 **`/znhs/api/...`**（与同一 FastAPI 实例一致）。若网关只暴露 **`/gray/api`** 并反代到本服务，再设为 **`/gray`** 且保证网关转发正确 |

静态资源路径：生产包用 **`/znhs/assets/`**；灰度构建为 **`/znhs-gray/assets/`**；开发构建为 **`/znhs-development/assets/`**（与 `app-public-base.js` 一致）。若由 **`main.py` 挂载 `frontend/dist`**，需保证版本包含 **`/znhs-gray/assets`** 挂载及灰度 SPA 路由（环境变量 **`GRAY_SPA_PREFIX`**，默认 `/znhs-gray`）；仍保留 **`/znhs/znhs-gray/assets`** 等兼容路径。若灰度静态全由 **Nginx 直出**，则要在 Nginx 配置 **`/znhs-gray/assets/`** 指向 `dist-gray/assets/`。

营销推荐 POST 使用 **`marketingRecommendUrl()`**（默认 **`/znhs/marketing/recommend`**）。若灰度网关路径不同，可在对应 `.env` 中设置 **`VITE_MARKETING_RECOMMEND_PATH`**。

### KeepAlive（本地直连 vs 主应用）

灵运 **`useKeepAlive`** 依赖主应用通过无界同步 `includedComponents`。**本地无主应用时该列表恒为空**，若仍套 `KeepAlive` 且 `include` 为 `[]`，页面可能**整页空白**。因此 **`App.vue`** 仅在 **`window.__POWERED_BY_WUJIE__`** 为真时使用 `KeepAlive`；直连开发时直接渲染 `<component :is="Component">`。

## 一套代码打出三套静态包（上传用）

源码只有一份；**区别在构建命令与输出目录**，一次可都打出来再分别上传：

```bash
cd frontend
npm ci
npm run build:artifacts
```

生成目录（均在 `frontend/` 下，**互不覆盖**）：

| 目录 | 对应环境 | 说明 |
|------|----------|------|
| **`dist-prod/`** | 生产 | 与 `npm run build:prod` 变量一致，等同于生产包 |
| **`dist-gray/`** | 灰度 | 与 `npm run build:gray` 变量一致 |
| **`dist-dev/`** | 开发构建包 | 与 `npm run build:dev` 变量一致（给联调/仿真环境用） |

**上传到服务器时**：`main.py` 默认读的是项目里的 **`frontend/dist/`**。任选其一环境的产物，在目标机上**整目录内容**放到 `frontend/dist/`（或你们流水线里 `cp -r dist-prod/* frontend/dist/`），**不要混放**三个环境的文件。

也可把 `dist-prod`、`dist-gray` 打成两个 zip，由不同主机解压到各自的 `frontend/dist/`。

单环境构建仍可用：`npm run build`、`npm run build:gray`、`npm run build:dev`（默认输出仍为 **`dist/`**，会覆盖）。

## 🔧 环境配置详情

**配置文件**: `.env.development`

```env
VITE_APP_PREFIX=development
VITE_APP_PORT=5173
VITE_API_URL_PREFIX=/znhs/
VITE_SUB_APP_ENVIRONMENT=true
```

**运行命令**:
- 开发模式: `npm run dev`
- 构建: `npm run build:dev`

**访问路径**:
- Base 路径: `/znhs-development`
- API 前缀: `/znhs/`
- 端口: 5173

### 2️⃣ 灰度环境（Gray）

**配置文件**: `.env.gray`

```env
VITE_SUB_APP_ENVIRONMENT=true
VITE_APP_PREFIX=gray
VITE_APP_PORT=20070
# 与同一台 FastAPI（/znhs/api）对齐；若网关独立使用 /gray 前缀再改为 /gray
VITE_API_URL_PREFIX=/znhs
```

**运行命令**:
- 构建: `npm run build:gray`

**访问路径**:
- Base 路径: `/znhs-gray`
- 后端默认 **`GRAY_SPA_PREFIX=/znhs-gray`**，与前端资源前缀一致
- API 前缀: **`/znhs`**（`apiUrl` 请求 `/znhs/api/...`）；若仅用 **`/gray`** 网关需反代到本服务 `/znhs/api`
- 端口: 20070
- 需与灵运主应用 `subAppList.js` 中该子应用的 url 路径后缀保持一致

## 🔍 技术说明

### vite.config.js 路径计算逻辑

```javascript
let base = appName
if (env.VITE_SUB_APP_ENVIRONMENT === 'true') {
  if (env.VITE_APP_PREFIX) {
    // 开发、灰度环境：带环境后缀
    base = `/znhs/${appName}-${env.VITE_APP_PREFIX}`
  } else {
    // 生产环境：VITE_APP_PREFIX 为空，直接使用 /znhs/
    base = `/znhs/`
  }
} else {
  // 完全独立运行（非子应用）
  base = `/${appName}/`
}
```

### 关键特性

1. **生产环境特殊处理**: 生产环境的 `VITE_APP_PREFIX` 为空，使 base 路径直接为 `/znhs/`，符合实际部署的 URL 结构
2. **灰度环境隔离**: 灰度环境使用 **`/znhs-gray/`** 作为子应用 public path，与生产 **`/znhs/`** 并列（由网关与 `GRAY_SPA_PREFIX` 约定）
3. **开发环境独立**: 开发构建使用 **`/znhs-development/`**，便于本地调试

## ⚠️ 注意事项

1. 配置上都按 **灵运 wujie 子应用** 约定（`VITE_SUB_APP_ENVIRONMENT=true`）；**本地开发无需真实主应用**，直连即可测页；灰度 / 生产需提供主应用入口并完成接入。
2. 生产环境的 API 前缀为空，需要确保后端路由配置正确
3. 灵运主应用的 `subAppList.js` 需要配置对应的子应用路径
4. 构建前请确认使用正确的构建命令以匹配目标环境
